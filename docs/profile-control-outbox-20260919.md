# 画像控制事件事务演练（2026-09-19）

接续 [旧容器存储清点与恢复检查点](profile-storage-control-20260919.md)。
本批验证生命周期变更与最小控制事件的事务一致性，不是生产 outbox 上线。

## 已确认的落点

用户选择先用服务器独立目录，不覆盖整机丢失。已创建
`/opt/smart-assistant-control`，核对为 root:root、0700、非符号链接、空目录。
它位于业务发布和普通备份目录之外；没有配置定时任务、导出真实记录或新增密钥。
目录存在不代表已有有效备份，也不抵御 root 误操作、同盘损坏或整机回滚。

## 本批验证的合同

`scripts/fixtures/profile_control_outbox.sql` 只能安装到本轮自建的
`profile_control_outbox_fixture` 空生命周期测试库；其他数据库或非空基线拒绝执行。
该文件不在生产迁移目录，也没有被应用启动流程引用。

- 生命周期新增从 generation=0、分析开启开始；状态变更须进入下一代次。
- 暂停、重新开启或代次推进与最小事件在同一事务内完成。
- 重复写相同代次/状态不产生额外事件；缺失控制流或事件落库失败使整个事务失败。
- 事件仅有 sequence、event_id、source_id、user_id、generation、analysis_enabled。
  不携带画像、聊天、订单或凭据；用户标识本身仍需访问保护。
- 单例计数行在事务内分配连续序号，不使用会因回滚留下空洞的数据库 sequence。
  跨用户提交也受这行锁排序；读者看不到尚未提交的事件或提前推进的水位。
- 合成策略拒绝生命周期删除、身份变更、回退/跳代以及同代次重新开启。
  这不代表正式账号删除/重新开启接口已完成适配。

并发用例使用两个真实 PG 连接：A 修改用户一并持有事务；确认 B 修改用户二时
阻塞在锁等待后，显式回滚 A；B 随后提交，序号仍连续。用 `pg_stat_activity`
确认同步点，设置等待预算，不依赖固定睡眠时间猜测先后顺序。

## 下一步与明确限制

当前 outbox 只在一次性数据库验证。**同业务库的事件表不等于独立控制备份，也不是落盘确认。**
生产接入还需：

1. 现有生命周期非空基线的短暂写屏障与完整快照登记；该演练故意拒绝为历史数据补造事件。
2. 正式业务事务接入及并发压测。全局计数锁会串行化控制变更，需限制事务时间，
   防止长事务影响其他用户；不能把该样例直接作为高吞吐生产方案。
3. 在已选目录实现受限导出、临时文件 fsync、原子发布和目录 fsync；以一致性读导出连续水位，
   校验来源、完整性和代次后才记录确认。中断/磁盘满/重复导出都必须有可重复验证的行为。
4. 独立维护可信最新水位，防止数据库恢复后把旧 outbox 当成新来源续写，或用旧检查点覆盖新记录。
   数据库内标志在数据库回滚后也会回退，不能单独承担恢复放行。
5. 生产恢复仍须关闭入口、消费者，完成跨存储屏障和逐目标验收后才能放流量。

`LEGACY_STORAGE`、`DERIVED_COPIES`、`BACKUP_RESTORE` 仍 BLOCKED，全量画像删除入口保持关闭。
