# 统一客服表达（2026-09-17）

## 设计与范围

在 Common 的 `CustomerReplyStyle` 维护统一规则，由 `PromptBuilder` 注入商品、订单和 Router 兜底 Agent；资料问答及多服务结果汇总也复用同一规则。只改变表达方式，不添加模型调用、不增加独立服务，不改变工具权限、事实校验、路由职责或订单审批边界。

- 简单问题一至三句，先回答当前问题；对比或复杂问题才用列表。
- 不每轮套用“您好 / 已为您查到 / 抱歉”，不卖萌、不责怪用户、不用泛泛的反问结束每条回复。
- 用户焦急或投诉时回应具体困扰，再解释核实结果或下一步；不贴情绪标签，不虚构加急、催办、退款时效或人工转接。
- 缺信息时只问当前任务需要的关键字段，不重复询问已知信息；普通政策咨询不索要订单号。
- 保留金额、订单号、型号、库存、预算结论和资料出处，隐藏内部函数、节点、商品编码、检索置信度及原始异常。
- 查询不到、尚未核实、明确没有、执行失败及结果未确认仍是不同状态。涉及写操作且结果未知时，保留核查原操作、避免重复提交的提示。

固定回复同步调整：空订单与订单列表、缺订单号、无匹配商品、资料不足、失败与排队提示、情绪前缀和前端进度信息。取消/门禁事件类型和恢复入口规则不变。

答案缓存切换到 `consumer:semantic-answer:v3:`，新提问不复用旧风格的回答。旧缓存自然过期，不删除或改写历史消息。旧对话中已经保存的回复保持原样。

## 部署

发布目录：`/opt/smart-assistant/releases/customer-style-v2-20260917`。更新 Consumer、Router、Order、Product 与前端；入口暂停后等待聊天队列排空再切换，保留备份，逐项核验制品与健康状态。未变更数据库结构、知识库、商品数据或已有业务记录；验证只新增专用普通账号及测试对话。

最终前端资源：`index-BlNDWwMA.js`。四个服务 SHA-256 记录在发布目录 `expected.json`，部署结果与真实问答验收分别记录在 `deployment.json` 和 `verification.json`；前端补充断流文案后已单独验证公网文件一致，制品记录见 `frontend-update.json`。

首轮实测发现询价答复仍主动邀约分期/发货、天气能力限制说明偏长，因此进一步收紧规则并本地复测后再次部署，未把首轮记为通过。另一个测试原本强制要求退款查询追问订单号，但测试账号没有订单、实际先查询账号并返回空列表也是有效行为；测试据此接受真实无订单结果，不改写业务结果迎合预设话术。

第二轮真实请求 `style-a2c2651eaa58426a8d844ed51f65e5bf` 将“帮我查一下退款进度”错误规划为下单信息说明，直接进入固定清单，跳过了订单查询。这不是语气问题；保留失败验收，补充 `QUERY_ORDER / READ` 与退款申请、下单说明的明确对照，不改动订单写操作和审批权限。另将固定的缺参数提示只输出允许的业务字段名称，不再透传 `REFUND_ORDER`、`order_id` 或规划指令。Router 追加部署记录见 `router-v3-deployment.json`。

后续人工检查发现，“问了半天还没说明白”未命中负面词库，导致普通询价答案被复用；补充相关表达后由既有 `TurnInsight.bypassAnswerCache()` 阻止复用，让当轮共情策略生效。这里沿用轻微负面的 NORMAL 队列等级，不把抱怨直接升为最高优先级。Consumer 追加部署记录见 `consumer-v3-deployment.json`。

人工复核再去除共情前缀后重复出现的“您好”，只处理开头称呼，不删除商品、金额或状态。46 项相关测试再次通过，最终 Consumer 制品记录见 `consumer-v4-deployment.json`。

当前源码未注册天气查询工具（GeneralToolCatalogRegistrarTest 明确排除 queryWeather），因此天气场景检查的是简短、真实的能力限制说明，而不是声称已实现实时天气。商品未指定型号的场景单独验证澄清语气。

最终线上 8 个真实问答场景通过：询价库存、空订单、缺商品名称澄清、不可用天气能力说明、退款进度查询、退货政策、用户给定资料问答和不满情绪下的重复追问。接口均正常结束；退款查询没有索要下单资料，资料问答保留 18 个月事实，情绪答复没有重复称呼或虚构加急动作。实际答复示例：“抱歉给您带来不便。AirPods Pro（第二代）目前售价 1999 元，库存充足，可以购买。”

这是第一版统一风格，不是保证所有生成结果都严格一至三句：人工观察仍有澄清时补充商品候选、能力限制说明附带额外引导的情况，作为后续话术精简项保留。8 项通过指业务与本轮验收断言，不代表任意问法下的完美话术保证。线上测试为真实 HTTPS/JWT/SSE 请求；不将本地 SSR/JSDOM 测试描述为真实浏览器点击验收。
