# 可恢复画像清理任务（内部基础设施）

本批封闭旧的无请求身份写入口，并增加持久任务、逐目标回执和两个已实现的清理适配器。
`profile.cleanup.enabled` 默认 `false`；没有新增删除/恢复 HTTP 接口或页面，不暂停或清理现有用户。

## 请求准入

实体提取必须携带原始问题和请求 ID，联查已有准入哈希及当前有效代次；不能在完成后重新签发准入。
商品画像旧同步/异步入口拒绝无请求身份调用；显式准入入口只解析已有凭据，模型返回后仍用同一代次提交。
暂停、缺少凭据、问题不匹配或旧代次都不会进入模型。后续存储写入继续受生命周期锁约束。

## 持久任务与回执

- 同一用户及幂等键只产生一次代次推进和一个任务，先在事务中禁写，再由后台处理目标。
- 每个目标独立记录状态、尝试次数、错误类别和下次重试时间；不记录待删正文或异常全文。
- PG 目标删除受控快照、变更日志、实体事实、Agent 记忆和提交候选；删除与成功回执同事务。
- Redis 目标在 PG 禁写行锁内设置持久 PAUSED 屏障，核查用户索引中每条请求的所有者/代次/类型，
  然后原子删除请求投影、候选、完成标记、所有者、索引及旧实体哈希。
  所有者冲突或无法确认的无主正文不会被误删；屏障保留、回执重试。
- Redis 已删除但 PG 回执未提交时可安全重试；进程重启从 PG 继续；旧任务遇到新代次转为 STALE，
  不清理重新开启后的数据。错误重试间隔 30 秒；锁等待 500ms，PG 事务最多 5 秒。
- 账号、订单、聊天、准入摘要和生命周期墓碑不属于本批删除范围；不清队列、不操作其他用户。

## 不可省略的边界

`LEGACY_STORAGE`、`DERIVED_COPIES`、`BACKUP_RESTORE` 三个目标目前固定为 BLOCKED，
因此即使两个已实现适配器成功，任务仍是 PARTIAL，不得展示“全部删除完成”。
旧无索引 Redis、MQ 旧载荷/DLQ、Agent 文件需按真实存储实例清点；派生提示词/执行图/进程缓存、
备份恢复时墓碑重放仍未验收。Redis 网络取消也不是事务超时的强制中断保证。
后续副本清点、进程缓存移除及合成 PG 恢复演练见 [2026-09-19 进展](profile-copy-inventory-20260919.md)；
该演练仅验收 PG 子集，不改变上述三个 BLOCKED 目标，也不开放全量删除。
未来开放接口必须从可信登录身份获得用户 ID，另设管理员授权，不能信任请求体目标。

本批测试仅操作独立 PG/Redis 中的合成用户；线上只进行正常只读问答与健康验证，功能开关保持关闭。
