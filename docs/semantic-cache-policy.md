# 语义答案缓存策略

语义缓存位于 Consumer 调用 Router 之前；命中时直接返回，不再执行任务拆解和 Agent 链路。Consumer 不自行判断业务意图，只保存 Router 在正常请求完成后签发、且已经通过质量门禁的缓存指令。缓存不保存思考过程、工具参数、订单数据或待确认状态。

| 场景 | 是否缓存 | 默认有效期 | 失效条件 |
| --- | --- | --- | --- |
| 热门商品发现、商品分析、商品推荐 | 是 | 1 分钟 | TTL 到期 |
| 普通商品详情、价格、库存咨询 | 是 | 1 分钟 | TTL 到期 |
| 严格依据业务文档、规则、流程说明的只读咨询 | 是 | 最长 24 小时 | TTL 到期或知识文档版本变化 |
| 订单列表、订单状态、物流、支付等用户业务数据 | 否 | — | — |
| 下单、取消、退款、售后等写操作或待确认流程 | 否 | — | — |
| 闲聊、通用知识、创作、澄清、混合意图和无法确定的请求 | 否 | — | — |

## 判定与存储边界

1. Consumer 先执行精确匹配；未命中时只从 Route 已认证的同用户商品缓存和当前知识版本业务缓存中召回向量候选。
2. 未命中时 Router 的任务规划模型输出 `semantic_cache_category`，只允许 `PRODUCT_CONSULTATION`、`BUSINESS_CONSULTATION`、`NONE`。
3. Router 确定性策略再次检查所有节点；出现未知操作、写操作、人工确认、订单数据或非白名单混合节点时强制降级为 `NONE`。
4. 只有工作流完成、未澄清、非管理员操作且通过领域及全局质量门禁时，Router 才向 Consumer 返回 `semanticCacheEligible=true`；Consumer 不重新推断分类。
5. 缓存按用户隔离，保存问题、最终答案、语义向量、Agent/意图标识、到期时间和知识版本；不会跨用户复用个性化推荐。
6. 向量候选不是最终命中：商品召回阈值默认 0.76（基于线上 BGE 分数校准）、业务咨询至少 0.94，且 Top1/Top2 分差至少 0.03；随后由轻量模型进行双向语义等价、单意图、无新增意图和约束一致性校验，置信度至少 0.95，校验上限为 6 秒。商品阈值仅用于高召回候选生成，不代表最终放行；任何超时、不确定或校验失败都进入 Router。
7. 商品查询在前置命中阶段不会重新执行完整任务拆解，因此统一采用更保守的 1 分钟 TTL，保证热门结果不会误命中较长生命周期的数据。

## 复合问题与节点缓存

复合问题不会把整句答案写入 Consumer 前置缓存。Router 拆解后，`DISCOVER_PRODUCTS`、`QUERY_HOT_PRODUCTS`、`QUERY_PRODUCT`、`ANALYZE_PRODUCT_DATA` 和 `RECOMMEND_PRODUCT` 等只读商品节点可使用 1 分钟 Redis 节点缓存；缓存键包含用户、操作、结构化输入、画像和前置节点结果。订单、物流、售后及所有写操作永远不进入节点缓存，因此“热门商品 + 查询物流”只复用商品分支，物流分支仍执行真实用户数据查询。

## 文档变更失效

任一服务成功完成知识文档摄取后，都会原子递增 Redis 中的 `a2a:knowledge:version`。业务咨询缓存键和条目均携带该版本，Consumer 每次读取业务咨询缓存前刷新版本；版本不一致时立即旁路旧缓存并进入 Router 业务链路。
