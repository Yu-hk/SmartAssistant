# 请求级画像 Redis 原子发布

本批继续收敛画像派生副本，**不开放删除/恢复接口**，不修改真实用户画像代次。
PG 代次隔离、MQ 引用消息保持原有协议；Router 的可选等待预算不变。

## 已实现范围

- Consumer 在独立 Redis 实例内用一段 Lua 发布请求投影、候选、完成标记、
  `用户 ID | generation` 归属标记以及用户请求索引，避免正常并发下多次 SET 的中间状态。
- 先检查全部键类型、归属和代次，再写入。其他用户或不同代次不能接管同一请求；
  完成标记仍有效时，迟到的 PENDING、失败或重复候选均不覆盖已完成结果。
- 候选成功进入 PG 引用消息发布流程后，按归属、代次及候选序列化原文比较删除 Redis 候选，
  不无条件删除键。比较不符或 Redis 故障时保留到自然过期；投影、回执与索引不随候选移除。
- 配置 TTL 限制为 30～600 秒。归属及完成回执不早于该请求此前保留期限过期；
  用户索引保留时间不被其他短 TTL 请求缩短。
- 用户索引是 `routing:user-profile-index:<userId>` 的 ZSET：成员仅 requestId，
  分数为 Redis 服务端时间计算的保留截止时间；每次发布剔除到期元数据，最多 500 个有效成员。
  容量满时跳过可选画像，不驱逐其他请求、不阻塞业务问答。
- 完成键独立使用 `routing:user-profile-done:<requestId>`，归属键为
  `routing:user-profile-owner:<requestId>`；原投影/候选命名不变，Router 无需升级。

## 明确不提供的保证

- 这只是请求级并发保护和可盘点索引，不是用户级删除屏障。
  PG `requireGeneration` 与 Redis 脚本不在同一事务；跨存储迟到命令、恢复旧 Redis 备份、
  新 requestId 携带旧代次等情况仍需用户级墓碑、请求准入代次及全部读取端校验。
- Router 当前仍按 requestId 读取原投影。未完成全部读写端的代次协议前，不得开放删除入口。
- Lua 提供串行执行，不是任意错误下的事务回滚。脚本提前拒绝类型/身份/容量错误，
  但 Redis OOM、故障恢复等仍需运维恢复协议，不能宣称跨存储恰好一次或全量清除。
- 本脚本涉及多个不同哈希槽，仅适用于当前独立 Redis；Redis Cluster 会拒绝 CROSSSLOT，
  不自动退回非原子 SET。若迁移 Cluster，先统一键槽布局并同步读端。
- 不扫描、接管或回填无归属的旧键；旧键等待原 TTL 到期。索引不覆盖旧版本/其他写路径，
  候选 JSON 字节比较不一致的历史数据也只等待 TTL。没有清空数据库或历史队列。
- 实体画像、Agent 文件、派生审计副本、备份清理和完整删除任务回执仍是后续工作。

## 验证

单测验证脚本参数、输入限制、失败降级、旧代次中途失效不发布等行为。
`ProfileRequestRedisIntegrationTest` 使用显式指定的专用 Redis，覆盖原子发布、
跨用户/代次隔离、终态保护、类型错误、旧键拒绝、条件退休、TTL、500 成员上限及并发竞争。
测试仅删除本次生成的精确 fixture 键，不使用 FLUSHDB 或全局扫描。
CI 要求 10 项真实 Redis 测试全部执行，缺报告、跳过或失败均不可通过。

## 部署要求

仅更新 Consumer，无数据库迁移。暂停入口、排空业务与画像提交队列后切换，保留上一包备份。
切换期间不混用两个完成键协议；需要回滚时先排空在途请求并等待本批键过期。
不能借本批回滚到不认识 v2 引用消息或不具备 PG 代次隔离的旧版本。
