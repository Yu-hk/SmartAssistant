# 聊天补充信息表单

## 范围与边界

- Consumer 将成功回复中明确的参数询问转换为版本化 `clarificationForm` 展示协议；只允许重量上限、预算、城市、订单号、商品名称/类型和购买数量六种字段。
- 这是保守的展示层适配，不是通用语义槽位识别器。未知话术、二选一条件和未支持字段保留文字澄清，不生成猜测字段；失败或等待审批的回复不生成表单。
- 只在当前会话最后一条已完成的助手回复下展示。旧表单、生成中、失败、暂停或结束会话不能提交。澄清期间隐藏会结束会话的评价卡。
- 同步提交锁防止快速重复点击；数值需大于零、数量为整数。用户可以改用文字回答。
- 表单提交仍使用当前会话的普通聊天接口，按既有字段语法发送补充信息；不会创建新会话，不是下单、付款或退款授权。原有后端鉴权、业务校验和审批门禁继续生效。
- Router 将 `补充信息：` 识别为连续对话，保留前文商品与筛选条件。前端展示标签“预算上限”提交为后端已有语法“预算为”。
- 仅预填本轮问题中可明确识别的重量/预算数字；不将回答中的示例数字作为用户选择，不将“1万元”误填为“1元”。用户仍可修改预填值。
- 历史查询在原有会话归属校验之后重建表单展示信息，无新表或第二份表单个人信息存储。刷新后可重新填写；不额外持久化未提交草稿。
