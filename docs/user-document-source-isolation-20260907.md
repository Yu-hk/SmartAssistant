# 限定用户资料问答隔离修复（2026-09-07）

## 范围与实现

原问题：题目明确给出“蓝牙5.3、续航30小时”，并要求仅依据所给资料，但商品 RAG 注入了无关目录证据，生成和校验都排除了用户原文。

- `UserDocumentContext` 在原始请求上识别明确的“仅依据/只根据资料”限制，将引号、代码块或 `【资料】…【问题】` 中的正文与问题分开，生成版本化 SHA-256 资料指纹。引用内容本身不能选择资料范围。
- Router 在现有安全/情绪与配额检查之后、RAG/历史拼接/模型任务拆解之前，将 USER_ONLY 请求交给独立的 `UserDocumentQaService`。不让规划摘要替代资料，也不调用业务 Agent。
- 商品直连入口同样拦截 USER_ONLY 请求，避免绕过 Router 时再次自动检索。
- 执行器无历史、无检索依赖、无工具回调。保留统一安全、PII、调用预算、Token 和提示审计；资料中的指令不具备操作权限。生成和忠实度校验使用同一份资料。
- 缺少可识别正文时请求用户补充；生成/校验失败时关闭该路径，不回退到外部商品查询。
- Consumer 对 USER_ONLY 请求跳过所有语义缓存读取和写入，旧缓存也不可命中。资料指纹为未来严格隔离的精确缓存准备，本次不启用资料缓存，不用相似度复用用户文档。

本次优先完成明确限定来源的隔离。未限定来源的知识库查询及允许结合资料的旧流程保持原样；没有宣称完成任意附件解析、跨轮文档继承或混合来源冲突裁决。正文无法识别时澄清，不猜测资料内容。

## 本地验证

134 项定向后端测试通过，三个服务 Maven package 成功，包括：

- 原文/问题分离、资料指纹变化、资料内指令不能决定范围；
- 无正文不调用模型、注入拦截仍生效、无工具回调；
- 无依据数值被同一资料校验拒绝，模型失败不改用外部来源；
- 路由先于强制 RAG、历史与规划执行来源隔离；
- 商品直连不进入 RAG/商品 Agent，Consumer 不读写旧缓存；
- 原有商品、路由、缓存、DNS、循环守卫回归。
