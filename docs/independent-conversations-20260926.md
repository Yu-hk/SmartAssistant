# 独立会话并发（2026-09-26）

- 同一账号可创建、查看和继续多段会话。新建会话不会关闭或暂停旧会话；跨浏览器也不再争夺账号级所有权。
- Redis `conversation:gate:{userId}:running:{sessionId}` 保证每段会话一次只执行一轮；请求 ID 可重新附着，其他请求被拦截。关闭、删除仅检查目标会话。
- MQ 派发准入键按账号和会话标识隔离；同一会话的未完成或结果不确定请求仍阻止后续派发。业务操作自身的幂等键与权限检查保持不变。
- 表单补充仅允许账号拥有、已创建且未关闭或暂停的目标会话，不会创建新会话。
- `20260926_allow_independent_conversations.sql` 移除账号单活跃唯一索引，并将历史因互斥而暂停的会话恢复为可继续状态；`CLOSED` 不变。先让旧服务请求排空，再执行迁移和部署新 Consumer，最后更新前端。
- 旧版 `/sessions/active` 保持兼容响应，但不再返回账号级会话所有者。旧版前端缓存应刷新。

回滚 Consumer 时不应自动恢复账号级唯一索引：新版本可能已产生多段活跃会话。可回退服务代码，但仍保持索引移除，并在恢复新版本前避免再次启用旧版单会话前端策略。
