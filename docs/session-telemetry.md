# 回复来源与统计一致性

2026-10-01 对专用 QA 的四条请求逐一检查调用审计和限定时段的 Consumer 日志：Edge 零 Token、零工具那条请求有明确的答案缓存命中记录。另一浏览器的新请求执行了实时流程，不能仅以不同请求的成本不同判定统计丢失。

## 合同

- 来源仅接受 `fromCache` 的布尔值，缺少或类型错误均未知。零 Token、空工具列表都不用于推断来源。
- SSE 的 init 和正常最终 response 传递来源；按会话所有者授权的历史读取从审计恢复来源。
- 复用现有 `route_method`，明确来源分别记录 `STREAM_CACHE` / `STREAM_LIVE` 和 `ROUTER_CACHE` / `ROUTER_LIVE`。旧方法名与未知方法名都不推断回填。无需新增表、迁移或修改缓存资格规则。
- 侧栏来源属于最新助手轮次，工具/Token 属于会话累计；切换到下一轮不继承上一轮缓存标记。
- 保留服务端已有用量快照和完整性状态，不复制原答案生成成本、不伪造调用。缓存等价性校验、上下文预处理仍可能产生费用，显示值不是全链路账单。
- 本次不调整 Ragas 四维结果、检索策略或线上权重。

## 验证

后端覆盖严格布尔值、审计往返、缓存/实时均可零用量、旧零记录保持未知、SSE 持久化及所有者过滤；前端覆盖历史恢复、最新轮次重置、真实零与缺失分离、侧栏来源说明。生产只用合成 QA 咨询，核对同一轮在 Chrome、Edge 和刷新后的来源与统计一致；不同请求的统计不要求相等。
