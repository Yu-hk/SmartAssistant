# 有界自动重检索：实现、上线证据与限制

2026-10-01，生产 Product 已启用 `bounded-kb-feedback-v1`。这是在线一次补检与安全比较，不是将 Ragas 的四项模型评分塞进每次请求，也不是“评分不够就不断检索”。

## 在线流程

1. 商品目录事实、型号核实与明确未知字段优先走既有确定性路径；下单、支付、退款、地址等写请求不参加补检。
2. 正常首轮 RAG 后检查有限分数、降级/中断状态、上下文预算以及问题词项覆盖。词项覆盖是廉价缺口代理，不是上下文召回率、忠实度或置信概率。
3. 仅知识类只读问题且有缺口时，最多增加一次知识库查询。继续使用原问题、原知识库选域和调用者完整租户/用户/角色/密级上下文；不重跑 LLM 规划器、改写器或业务工具。
4. 知识库候选上限从 5 扩至 8。补检局部融合使用 sparse/dense 路径权重 0.7/0.3；这影响 Product RRF 路径融合，不代表已改动知识库内部 BM25/BGE 权重。非知识库路径保持不变，不热修改其他请求配置。
5. 解析实际知识片段的标题、正文与 CID。保留首轮知识文本原文，仅增加正文含缺词、标题与问题显式名称对应且与原证据名称一致的片段；不能把 CID 当实体。含糊或解析失败则不扩张到其他商品。
6. 候选须保留原匹配词、引用和证据原文，覆盖至少 0.6、提升至少 0.1，并通过原质量阈值与 12000 字符上限，否则保留首轮结果。无资料仍须明确说证据不足。
7. 每实例最多两个补检工作线程、零等待队列。补检调用方等待上限 1500 ms；超时取消任务、错误/忙碌/中断安全回退。底层调用若不响应线程中断可能仍占用线程，所以有容量限制，不声称所有下游工作在 1500 ms 内已彻底停止。

普通生成阶段原有 Agent 工具行为没有改变；“最多一次”是本补检环节的上限，不是整个系统总工具调用数。没有扩大订单或资金操作重试权限。

## 观测与开关

实际请求 RETRIEVAL 阶段 `metrics.evidenceTrace.feedback` 记录开关、状态、是否尝试/接受、前后覆盖计数、实际选中轮次。新增诊断不保存词项、问题原文、证据正文或用户标识；既有 StageTrace 的保留策略不变。缓存命中不会触发新补检，必须与实时来源区分。

- `PRODUCT_RAG_AGENTIC_AUTOMATIC_RETRY_ENABLED=true`：本次生产启用；仓库默认 false。
- `PRODUCT_RAG_AGENTIC_AUTOMATICRETRYENABLED`：生产同时设置为同值，适配规范化环境绑定。
- `PRODUCT_RAG_AGENTIC_RETRY_TIMEOUT_MS=1500`，以及规范化别名 `PRODUCT_RAG_AGENTIC_RETRYTIMEOUTMS`：默认 1500、约束 100～3000 ms。

新开关开启时不再同时运行旧的 LLM 补充检索循环，避免叠加重试。关闭新开关仍遵循已有旧开关配置；本次生产旧自动补充没有另行开启。回滚须同时还原四个环境项/部署配置，不能只改一份文件却保留运行容器旧值。

## 冻结对照与四维结果

隔离实验使用实际生产 BGE、Common 依赖及候选 Product 类。64 个既有冻结问题、65 文档与两道独立六事实控制共 66 例，三轮重复；金标不交给检索器或生成模型。最终结果：

- 三轮所选证据一致，64 例保留基线证据，未新增非金标 ID，没有 ID 召回回退；基线召回已高，不声称这 64 题取得额外收益。
- 两道六事实控制均从 5/6 到 6/6，排除私有和错误知识域文档。
- 初版补检曾加入无关商品资料，未发布。增加同名称正文补缺与原文保留后重新执行全部对照，只有最终包通过门禁。

在控制题实际入模片段上生成四份答案（基线/候选各两份），用冻结参考答案进行三轮真实 Ragas 0.4.3 评判，共 48 项分数、零评分错误。参考答案只用于评判，不给生成模型。下表为三轮中位数：

| 控制问题 / 策略 | 上下文召回率 | 上下文精度 | 忠实度 | 答案相关性 |
| --- | ---: | ---: | ---: | ---: |
| 六事实 / 基线 | 0.8333 | ≈1 | 0.8750 | 0.6440 |
| 六事实 / 补检 | 1.0000 | ≈1 | 1.0000 | 0.6332 |
| 反序六事实 / 基线 | 0.8333 | ≈1 | 1.0000 | 0.2758 |
| 反序六事实 / 补检 | 1.0000 | ≈1 | 1.0000 | 0.6885 |

第一题相关性略下降，第二题改善；不能说四项全部提高，也不能用尚未校准的 0.8 等阈值作为全生产放行标准。重复的是评判，每个策略答案没有重复生成。这里只证明有界缺口补检与安全回退，不代表真实用户分布收益或完整商品语义实体识别。

## 可复现工具

- `scripts/run_bounded_feedback_server.py`：固定隔离路径、冻结 64+2 例、三轮实际检索对照与门禁，不接入业务 DB 或真实会话。
- `scripts/collect_bounded_feedback_ragas.py`：从实际格式化证据生成合成答案，核对 CID/顺序，参考答案不进入生成。
- `scripts/build_bounded_feedback_overlay.py` / `apply_bounded_feedback_overlay.py`：固定旧包与类摘要、限定新增/替换范围、拒绝覆盖已有工件。
- `scripts/verify_bounded_feedback_live.py`：对限定 Product 端点执行合成只读咨询，核对实际包与请求轨迹，不假冒浏览器验收。
- `scripts/release_bounded_feedback_20261001.py`：当前服务器布局的一次性受保护发布工具；金丝雀、排空、配置预检查、健康核对、上线后检查失败回滚。不是任意版本通用发布器。
