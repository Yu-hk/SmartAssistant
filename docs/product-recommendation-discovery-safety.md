# 商品推荐：目录故障、销量口径与需求澄清

日期：2026-09-14。状态：本地实现与回归验证，尚未部署本次改动。

## 修复内容

- JDBC 热度只使用 `products.sales_30d`；删除对历史订单数量的叠加与重复查询降级。文案明确为目录记录的站内近 30 天销量，不代表全网流行程度。这不是新增销量定时统计任务，字段的更新仍由目录数据维护方负责。
- 生产 Bean 只读取 JDBC 目录，移除 `product.catalog.mock-fallback-enabled` 开关；原两参数 JDBC 构造器保留源码兼容性，但不再使用传入的模拟后端。`InMemoryProductBackend` 仍可由测试显式使用。
- 目录不可用与成功的空目录严格区分：字符串工具返回结构化错误，列表读取抛出专用异常，执行接口映射为 `PRODUCT_CATALOG_UNAVAILABLE` / `RETRYABLE_FAILED`。不会把故障解释为“没有商品”，也不会返回模拟价格、库存。
- 推荐正文增加目录支持的理由：是否符合预算、已知库存，以及用户关注点对应的规格。评分和销量只作为参考，不证明拍照、降噪、续航等专项性能；没有规格证据时明确不能证明满足偏好。金额仍由程序生成，默认不展示预算差额。

## 无明确品类时的行为

| 示例 | 当前处理 |
| --- | --- |
| 轻便、续航长；预算 2000 元 | 请求确认商品品类和用途，不随意猜测手机或电脑 |
| 最近流行什么商品 / 推荐几款热门商品 | 返回跨品类目录列表及销量依据，不强制模型挑选唯一商品 |
| 推荐一款无线耳机 | 按目录品类筛选，再进行结构化分析与审核 |
| 当前真实目录没有满足预算的商品 | 返回无匹配结果，与目录不可用错误区分 |

澄清和浏览标记随发现结果传递到后续分析、推荐节点，避免再次要求模型生成唯一推荐，或将澄清误判为“空商品目录”。存在失败或冲突前驱时不直接采用这些标记。澄清使用 PASS 质量状态，不作为商品生成失败。

目前特征处理是保守规则，不宣称已经实现任意自然语言特征的语义召回。更进一步可增加重量、续航、功能等可验证字段与同义词索引：有明确证据且品类唯一时直接筛选；跨品类或证据不足时继续澄清，不能把销量排序当作特征匹配。
