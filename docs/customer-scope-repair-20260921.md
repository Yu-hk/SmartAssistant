# 客服验收失败后的修复（2026-09-21）

## 已有线上证据

上一候选版本在六轮公开验收中出现耳机推荐失败和退货政策偏题，已回滚到
`cross-store-20260921`。回滚版本也复现推荐失败；政策问题在一次对照中正常。
没有证据将两项问题均归因于执行预算补丁，也没有将关键词命中视为语义质量认证。

## 本轮变更

- 中文金额：原预算正则仅匹配阿拉伯数字，新增七项失败用例后修复“两千以内”等正式
  中文整数金额；“三千五”“一两千”和未确认范围返回澄清，不当作无预算。
- 约束来源：Router 的商品子任务只传模型描述，原始问题虽在 `_replyScopeQuestion`
  中，却没有用于发现/分析/推荐的预算校验。现在这些阶段优先保留原问题的明确预算；
  不将模型改写后的更高金额当作用户授权。
- 结构化推荐：程序公布每款商品可引用的证据字段和限制项；校验失败给模型一次有针对性
  的纠正机会。日志仅记录稳定原因分类，不记录模型正文、商品正文、用户画像或密钥。
  未知商品、超预算、缺失证据、额外金额字段和审核拒绝仍不能成为成功推荐。
- 政策规划：对明确只询问退换货政策的问题检查计划范围。发现商品发现/推荐、写操作
  或完全偏题描述时，仍由模型重新规划一次；再次偏题则不接收该计划。不改写实际订单
  操作或混合意图，不由规则生成政策答案。

## 第一轮线上复测及发现的汇总问题

`customer-scope-20260921` 的四服务及网关健康通过后，六轮公开 API 用例的旧自动检查
全部通过。人工复核确认：预算两千以内的耳机推荐已返回 AirPods Pro（第二代），售价
1999 元、未超预算，且提供目录证据；退货政策返回 `[CID:ORD-REFUND-001]` 引用。
对照 PostgreSQL `products` 表核验 AirPods 的名称、1999 元价格、库存、规格、1880
站内近30天销量、4.9 评分和 9200 条评价一致。没有访问真实用户的订单或对话正文。

但热门商品列表仍完整重复两次，因此未推送。代码复核发现 `browsingOnly` 结果被下游
节点原样传递，最终又逐节点拼接。新增仅针对相同商品浏览答复的合并去重：保留全部
审计结果，先检查结构化冲突，不合并订单或不同答复。ResultMerger 与政策相关 19 项
测试通过。验收脚本补充整段重复检查，Python 测试增至 10 项通过。

## 第二轮复测与遗漏路径修复

`customer-scope-v2-20260921` 在服务器隔离测试 218 项通过，但公开复测的热门商品
场景仍被重复检查判为失败，因此仍未推送。其余五轮通过，测试会话全部关闭、令牌撤销。

该合成请求的 Router 日志显示：模型计划缺少商品分析的发现依赖，被拒绝后进入备用
规划路径，两个商品节点均使用 `product_agent` 别名。上次修复存在两个遗漏：仅识别
`product` 名称，且备用汇总未调用去重。现在复用执行器已有的标准名称归一化规则，
并让备用汇总使用同一去重逻辑；不去重订单结果或不同内容，也不删除节点审计。

新增别名及备用规划两项测试在修复前均失败，修复后路由相关 51 项通过。CI 增加
ResultMerger 13 项、预规划执行 31 项最低测试数量门禁。

第三版重新运行完整客服 CI 集合 314 项和 Python 工具 10 项，均无失败、跳过。
服务器实际候选字节码隔离测试 250 项通过（common 79、product 120、router 51），
临时测试资源已移除；四服务 common 字节哈希一致，发布预检保留原环境、镜像、DNS、
控制目录和上一版容器配置。公开复测结果待实际完成后追加。

再次连接 Edge 页面仍返回 `nodeRepl.fetch request failed`，因此浏览器验收仍未完成；
本轮不会将接口验收写成真实页面已验收。
