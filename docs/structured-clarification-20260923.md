# 受约束的模型澄清表单（协议 v2）

> 本文保留初版实现与当时验证记录。后置通用模型分类已由[执行层补全协议](domain-clarification-20260923.md)替代，以避免跨业务字段混用；以下模型生成步骤不再是当前实现。

## 生成与提交

1. Consumer 在最终助手回复后调用轻量模型，只分类所缺字段和原文证据；不挂工具、不执行业务。通过既有 AiChatService 的治理链调用。
2. 后端审核 JSON 形状、字段白名单、重复字段、连续原文证据及询问特征。模型不能定义控件、校验规则、操作或预填值。不符合规则、失败状态、超时、模型故障都只保留原文字回复。
3. 返回后端签名的 v2 表单，绑定账号、会话、来源请求和 15 分钟有效期。签名密钥由已有 JWT secret 通过独立用途派生，不能当作登录令牌使用；无有效密钥时不发放表单。
4. 前端提交 `{token, values}`。Consumer 在既有会话租约内重新验签、验证最新归属记录、精确字段集合、字段值和防重标记，再自行构造补充信息文本；不采用浏览器传入的 message 作为表单业务事实。
5. 同一来源轮次的多个凭证共用哈希防重标记（Redis，15 分钟），不记录账号、正文或输入值；Redis 不可用时拒绝表单提交。标记在派发前写入，失败后不自动重试业务；用户仍可文字澄清，业务确认流程保持不变。
6. 表单走 `acquireExisting`：Redis Lua 在创建租约前原子核对该会话仍是活跃所有者；关闭、暂停、过期、其他活跃会话均不能通过表单隐式开启或切换。普通聊天的原有新会话行为不变。

## 服务端字段规则

| 字段 | 规则 |
| --- | --- |
| 重量上限 | 0.001–1000 公斤，最多 3 位小数 |
| 预算 | 0.01–10000000 元，最多 2 位小数 |
| 数量 | 1–10000，正整数，不接受小数写法 |
| 城市 | 最多 40 字，名称字符集，不接受换行、控制字符或操作指令 |
| 商品名称/品类 | 最多 100 字，名称字符集，不接受操作指令 |
| 订单号 | `ORD-` 开头，后续为 1–64 位字母、数字或连字符 |

这些是本应用的输入范围，不证明城市存在或商品/订单有效。具体商品、库存、订单归属、可退款性继续由相应业务服务核验；表单不是下单、支付或退款授权。普通文字消息仍走原业务流程。

## 历史、降级和用量

- 不新增数据库表或保存第二份填写草稿。旧的 v1 无签名表单不再渲染或提交。
- 授权历史加载后只为最后一条成功助手消息申请新表单；服务端再次查询该账号该会话最新记录。未知、已删除或非当前来源不返回表单。暂停和关闭会话不能通过原会话门禁提交。
- 模型分类采用 2 个工作线程、无等待队列、默认 2500ms 等待上限（配置最高 5000ms）。超时取消等待；底层供应商可能继续处理，但有界线程池限制并发积压。
- 正常聊天中新增分类 Token 与业务 Token 合并，任何一段用量未知则合计未知，不能将其视作 0。历史表单重建是独立模型调用，不改写原历史回合用量。
- 表单提交验证失败返回 422，不调用画像分析、路由或业务工具。前端说明未发起业务处理，保留文字补充入口。
