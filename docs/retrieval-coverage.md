# 商品覆盖检查与检索追踪

## 实施边界

本次实施前一轮建议的第一阶段：请求槽位覆盖、来源/排序追踪、重排失败保护和证据感知离线诊断。保留现有事实直答、确定性金额计算及有界忠实度修正，不新增业务写操作，也不让 Ragas 在线评分决定重试。尚未完成代表性留出集上的融合权重校准、评判器未知回答校准或自动缺失槽位补检索。

## 字段覆盖

`ProductFieldCoverage` 以解析后的请求为基准，逐商品检查它自己的字段，不用多个商品的字段并集替代局部要求。身份必须匹配目录编码；重复记录不当作覆盖。

| 状态 | 意义 | 行为 |
| --- | --- | --- |
| KNOWN | 身份确定，字段有非空目录证据 | 使用此字段事实 |
| UNKNOWN | 身份确定，字段显式 known=false 且无数值证据 | 如实说明资料未知，不重检索造数 |
| MISSING | 身份确定，但请求字段没有有效响应 | 不能称为完整回答；影子建议定向核查 |
| UNRESOLVED | 型号未确定、目录身份变化或重复冲突 | 请用户核实，不扩展到相似型号 |

覆盖完整仅表示每个所需字段有明确状态，不保证全部可回答、满足条件或通过 Ragas。现有逐字段条件与复杂残余条件保护继续执行。

商品事实服务返回 `fieldCoverage` 与 `evidenceTrace`，包括实际请求 ID、目录字段来源、按序 ID/文本 SHA-256、回答 SHA-256、计算方法和价格口径。不会把 BigDecimal 金额计算、运费/优惠未核实声明伪造为召回文档。遗留无实体解析的直答接口未升级为全槽位追踪，采集器不能把它冒充新版证据。

可解析的事实提问若进入 `ProductRagService`，优先读取绑定目录字段，不进入全局模糊重排；资料未知仍作为显式上下文。超过最终证据预算时安全拒答，不截掉一款商品后仍宣称完整。

## RAG 管线追踪与重排

真实管线记录各路候选的稳定文本指纹与排名、每个 Handler 后的融合结果快照、实际选中轮次、融合权重和格式化上下文指纹。接入商品流式服务的 RETRIEVAL 阶段，明确 `promptEvidenceInjected`。快照最多 32 阶段、每阶段最多 64 候选，单路展示最多 64；`totalCandidates` 保留真实计数。记录不含问题、历史、画像、模型思考或原始证据正文；已有阶段追踪自身的保留策略不被本次改变。

完整知识库内部 chunk 排序仍须从相应检索器单独取得：商品路径中的一条知识库结果可能已是聚合文本，不能宣称已记录每个数据库内部候选。本次目录评测不会借此冒充全流程检索 benchmark。

重排部分失败或返回非有限值时保持整个原融合顺序，避免把原始 RRF 小分数与语义大分数混排。基础设施标准错误继续向管线传播并标为降级。

可选 `product.rag.rerank.fusion-weight` 为有限 0～1；默认 **0.0**，维持原语义重排。候选实验公式为 `weight × (RRF / 最大 RRF) + (1-weight) × semanticScore`。该归一化是候选排序分，不是召回率或置信概率；不得仅因一次 Ragas 低分就改生产参数。

## 四维诊断

评测采集器要求新版实际响应 manifest；校验答案、证据文本、ID、顺序与槽位计数，旧数据集仍可评分但没有新的阶段判断。被修改的受控反例移除旧 manifest，仅保留其摘要，不用原完整覆盖声称来解释被删除的证据。

- 缺证据：只建议核查缺失商品/字段。
- 型号不明：核实实体，不能扩宽到其他型号。
- 忠实度低且有合计：先核验算术和实际政策上下文。
- 已明确未知但相关性低：先校准可回答性评判，不能编造未知值。
- 波动或执行失败：仍优先评判器/执行环境复核。

所有 `execute_retry=false`，无订单、余额、物流、商品或权限写入重试。缺少独立金标不能计算真实 ContextRecall。
