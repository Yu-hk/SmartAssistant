## 本轮交付

1. `scripts/release_artifacts.py`：只读采集实际镜像、JAR bind 路径、大小与 SHA-256；
   同时核对容器内文件，识别宿主路径更新但容器仍读旧 inode。按已知快照验证回滚后版本。
   不读取环境变量，不覆盖旧快照，不自动部署、回滚或修改数据库。
2. 15 项校验器测试覆盖正常、篡改、停止服务、错误挂载、快照格式、恢复原文件和无前缀完整镜像 ID 等路径，加入 CI。
3. `SmartReActAgentBehaviorBaselineTest` 以有序事件验证 6 条路径：工具结果先于下一次模型调用；
   每轮 Token 采集；确认先于工具执行；模型异常保持类型且不重试业务；空响应有界停止；
   Token 预算和迭代上限停止。配合已有 ChatClient、PhaseGate、工具执行、决策与故障测试运行。
   这是可观察行为的一部分，不是所有并发、压缩、取消和超时场景的完整证明。

## 下一批运行时代码变更的准入条件

- **文件并发**：先用两个独立 JVM 复现丢更新；以用户/Agent 文件为锁范围，限制锁等待；
  原子替换与读取失败拒绝覆盖；测试并发保存/删除、进程退出、大小上限、符号链接边界。
  本机文件锁不等于跨节点共享文件系统一致性，需要限定部署语义。
- **全量画像删除**：先确定用户授权和删除范围（PG 快照/日志、Redis 投影/在途候选、Agent 文件）；
  引入可审计删除任务与版本隔离，令删除前的迟到候选不能重新提交；逐存储幂等重试，
  失败状态不能标成已删除。备份保留与恢复策略必须一起说明，不通过清 Redis 宣称全量删除。
- **ReAct 拆分**：先补超时/取消/压缩/并行分支基线，再独立抽取预算与停止判定；每个 PR 保持
  工具确认、错误类型、Token、消息顺序和降级行为不变，禁止顺手重写整条循环。

上述三项仍是未完成项；本轮不扩张成未经专项测试的核心运行时重写。
