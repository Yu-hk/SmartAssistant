# 结构化意图与领域元数据硬编码审查

## 本轮已处理

| 调用链 | 原风险 | 处理 |
| --- | --- | --- |
| Product 特征查询 | “轻便/便携”被当作缺失重量上限；新增说法靠追加 `contains` | 已有的结构化特征解析器接入商品发现；新增“商务”定性偏好，并保留标签到发现结果。目录没有对应证据时只列同品类候选，明确不能声称符合偏好。重量/续航是定量约束，单位、正数、上限、重复值、续航场景和二选一冲突由确定性校验器核验。 |
| Product 商品发现 | 热度、库存、品类别名、场景词散落在条件分支 | 统一输出 `ProductDiscoveryIntent`，词汇由 `product-discovery-schema.properties` 提供；预算继续由封闭语法解析，校验多值/范围、正数上限与人民币单位。 |
| Product 推荐理由 | 拍照、降噪、续航、便携的触发词直接写在渲染器 | 解释性维度来自 `product-recommendation-aspects.properties`；只有用户问题与已核实目录规格同时匹配才提示“相关规格”，不将词命中当成性能证明。 |
| Consumer 商品录入 | 重量单位、续航场景与 Product 独立硬编码 | 录入词汇移到 `product-intake-schema.properties`；Common 的 `product-feature-domain.properties` 统一两侧重量/续航上限。近似值、包装重量、测试口径冲突仍拒绝自动采信。 |
| Order 补全与只读意图 | 必填字段、别名、标签和大量只读问法写在服务类内 | `order-clarification-schema.properties` 管理操作的必填字段及字段别名/提示；`order-intent-vocabulary.properties` 管理只读识别词汇。字段格式、未知操作、写操作禁止降级仍由代码校验。 |
| Router 模型降级分发 | 商品/订单关键词列表写在 Parser 内 | `fallback-dispatch.properties` 只配置粗领域分发，不引入订单字段解析，也不开放写操作权限。 |

## 不外置的安全边界

- `ClarificationRequest` 字段白名单、订单号/手机号格式、未知操作拒绝、审批/幂等与只读降级限制属于协议或安全校验，不因增添同义词自动放宽。
- Order 的封闭备用写请求语法保留；无法安全确定单项操作时拒绝生成提案。录入简介属于不可信数据，不能指挥提取器修改规则。
- 目录没有已核实的重量/续航事实时，定性偏好不能被转换为硬过滤条件；未知规格不能算匹配。

## 后续维护规则

1. 新增表达优先改对应服务的领域词汇配置，并补同义词与否定/冲突回归测试。
2. 新增定量字段必须扩展强类型意图、共享物理边界、确定性校验与目录证据契约，不能仅添关键词。
3. 业务模型输出只能作为结构化意图候选；数值约束通过校验后才进入查询条件。
