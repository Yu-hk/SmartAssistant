# 商品实体覆盖评测扩展 · 2026-09-30

## 范围与来源

本轮针对“能否适配大多数场景”的证据缺口扩充能力/安全契约，不读取、导出或重用生产用户原始对话。未找到具有来源与脱敏标注、适合直接复用的实体真实样本。新集为人工编写的 **64 个合成问题**、9 个场景类别，使用固定的测试商品与资料缺失商品，不代表线上流量分布。

数据：`smart-assistant-product/src/test/resources/product-entity-coverage.json`。运行 `ProductEntityCoverageTest` 后生成 `smart-assistant-product/target/product-entity-coverage.json`；CI 实体门禁同时上传旧提及金标和本轮逐例覆盖报告。

## 统计口径

- `DIRECT`：已认领，没有待核实标记，所查询字段不存在 `known=false`。
- `CLARIFY`：已认领但型号/条件需核实，或目录字段证据不完整。明确说明“尚未核实”也归此类，不当作完整直答。
- `WRONG_MATCH`：已解析到金标未允许的 SKU。
- `UNHANDLED`：当前闭合只读链未认领。写操作、知识库及非商品问题应交回既有规划/业务链，不意味着整个系统无法回答。

另外单独检查字段绑定、数量、必要/禁止出现的答案片段、非直答的报价泄露与基础设施失败。**错误 SKU 为零不等于所有答案正确**；其他契约错误会单列 violations，仍令 CI 失败。分类数量不是准确率；非直答不计入直答成功率。

## 首轮发现与修复

最初 61 例的原始检查为 55 例符合契约，6 例不符合：

1. 0 件与 100 件导致精确名称边界被数字挡住，闭合链没有认领。数字边界现先识别，数量不在 1～99 整数范围时要求核实、不计算总价；补测空格及小数数量。
2. “价格不超过 2000 克”虽然提示单位异常，仍输出价格条件符合。非法维度现在不进入数值比较，结果只能尚无法核实。
3. “续航多少小时”中的时间问法被误当作残余条件。仅开放式时长问法可消去问句单位；“至少 5 小时”等阈值仍要求明确场景，不能借用最大续航。
4. 资料缺失商品的重量/价格虽正确说明尚未核实，原评测分类器仅看澄清标记，误计为 DIRECT。改用结构化证据完整性判断；此两例是评测口径修复，不是新增商品资料或猜测答案。

加入三个边界问题后，本地 64 例均符合契约：DIRECT 31、CLARIFY 26、WRONG_MATCH 0、UNHANDLED 7。合成集契约通过率 64/64，不能解读为真实用户问题覆盖率或 Jev/Ragas 质量 100%。扩大数据集与针对暴露问题修复使用同一套样本，仍存在样本选择和开发集过拟合限制。

广泛商品回归两轮各 277 项通过，最终 JAR 构建成功；64 例金标作为其中一项报告型测试执行，而不是另加 64 个 JUnit 测试。Windows 本地继续使用 JaCoCo 路径绕过，远程门禁仍保持覆盖率要求。`git diff --check` 通过；Actionlint 容器未能运行，因为本机 Docker Desktop Linux 引擎管道不存在，不能声称本轮工作流已通过 Actionlint 或远程 CI。
