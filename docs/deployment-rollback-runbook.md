# 应用发布与回滚检查单

适用于当前单机 Compose 部署。不是零停机滚动发布保证；生产多副本切换需另行验证。
所有路径、挂载、版本以发布前只读盘点为准，不根据目录名称猜测 JAR 版本。

## 发布前

1. PR 基线、工作区变更范围、目标服务清单、测试结果和数据库兼容性明确。
2. 确认磁盘空间；只备份本次替换的 JAR/前端、配置文件引用与 SHA-256，不把密钥打进 Git 或日志。
3. 读取容器实际挂载与镜像标识。现有版本必须能原样恢复；首次失败回滚也要核对哈希及健康。
4. 迁移如不向后兼容，停止发布，先补迁移/恢复演练；不通过清空生产表解决问题。
5. 文档、CI、测试或开发命令变更若不改变运行产物，不重启业务服务；记录“无运行产物变更”，不能声称重新部署了新业务功能。

## 切换

1. 根据目标依赖进入维护/停止新接入；确认 MQ ready 和 unacked、运行中请求及后台提交可安全排空。
2. 运行中业务未排空则停止发布，不强杀订单操作、不清 Redis 执行权、不盲目重投递。
3. 停止待替换服务后替换已校验产物，保留原容器配置；启动并验证内部健康及服务发现。
4. 前端先发布内容哈希资源，再原子替换 index.html，保留上一版资源供已有标签页使用。
5. 恢复入口后验证公开健康（当前 nginx 为 `/healthz`，应用内部为 `/actuator/health`）、登录、普通账号只读查询、SSE 完成事件、工具和 Token 元数据。
6. 独立测试账号不得冒用真实用户或创建真实支付/退款。仅清理本轮明确归属的测试资源。

## 回滚触发与动作

- 触发：健康超时、鉴权异常、关键只读回归失败、错误率明显升高、首页引用不存在的资源。
- 停止新增接入，保留失败版本日志与哈希，恢复本轮备份的兼容 JAR 和前端入口。
- 重启目标服务并重新验证内部/公开健康与实际页面；回滚验证失败立即报告，不能仅因脚本 exit 0 宣称恢复。
- 涉及已提交业务数据时禁止逆向清库；根据迁移兼容性和业务补偿流程处理。
- 发布验收后按用户要求仅保留最近一次有效回滚备份；删除前核实精确目标，不清理业务卷、日志证据或未知文件。

## 发布记录字段

提交 SHA、时间、目标服务、前后 JAR/前端 SHA、备份绝对路径、迁移说明、
内部/外部检查结果、测试账号与请求 ID、失败与回滚情况、最终运行版本。
集成测试报告不替代线上验收；线上单次验收也不替代集群/故障测试。
