# 业务字段硬编码扫描与执行层归属

## 本轮范围

复查 PR #90，并扫描 Router、Consumer、Common 和前端中缺失字段、补全模板、阶段提示词和默认 FAQ。目标是消除跨业务字段推断，不是删除所有常量。

| 发现 | 处理 |
| --- | --- |
| Router 的降级解析器同时解析订单字段、校验收货资料和生成补全话术 | Router 只保留分词和领域分发；Order 的只读 `PREPARE_FALLBACK` 负责封闭语法、参数校验、缺失字段和业务说明 |
| Router 残留旧订单准备模板，包含“成交金额”等用户不应补填字段 | 删除两套旧模板，测试改为验证执行层协议，不再调用旧函数 |
| 规划提示词列出各订单操作的必填字段及固定空实体表 | 删除清单，依据目标 Agent 协议；只提取用户已明确提供的实体 |
| Consumer 收集阶段示例预设退款必问订单号、推荐必问预算 | 改为只解释执行层确认的缺失信息，不自行增加字段 |
| 默认 FAQ 将退款政策咨询也要求订单号 | 修正新建默认 FAQ 文案，区分政策说明与具体订单办理；不覆盖管理员已有知识库记录 |
| 前端所有表单的通用校验错误均提示订单号格式 | 改为指向当前字段提示，不引入其他业务字段 |
| 只读准备请求遇到旧版 Agent 404/405 会退到通用模型接口 | 禁止准备能力降级到旧接口，失败时停止，不让原始问题触发写操作 |

## 保留的边界

- `ClarificationRequest` 的领域/操作/字段白名单是协议安全边界，保留。Consumer 和前端的格式、长度、数值校验是输入边界，不能删除。
- Order 保留本领域的业务规则、别名和校验：下单收货信息、取消/退款原因、售后类型。它们不应迁到 Router，也不能由模型随意覆盖。
- `SlotStateMachine` 使用 Agent 已发布的词槽协议，不拥有业务字段表。本轮不把它替换成另一套硬编码。
- Router 的操作许可、读写分类、审批和幂等规则属于协调安全边界，保留。商品报价仍由 Product 核实，再交现有审批流程；用户预算不能成为订单金额。
- 未知操作、复合/否定指令、重复字段、伪造价格、超范围原因均不能形成降级写计划。资料准备本身不调用模型或变更订单。
- 本地已有未提交的 Product 特征架构改动不属于本轮，不纳入提交与部署。历史 FAQ 数据不自动改写。

## 验证要求

- Order：缺少退款原因只询问原因；已给商品/姓名不重复询问；不接受用户成交金额；混合命令不能生成提案。
- Router：准备调用只有只读能力；不复用历史原因；域失败/未知操作不进入写流程；所有合法提案仍需原有用户审批。
- 协议：准备端点 404 不调用旧接口。
- 前端：商品字段错误不显示订单号要求。
- 部署验收另记录在本轮发布目录，不能把接口测试称为真实页面视觉验收。
