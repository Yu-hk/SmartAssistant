# 旧容器存储清点与恢复控制检查点（2026-09-19）

接续 [压缩备份目录覆盖](profile-archive-inventory-20260919.md)。用户已确认没有本机备份目录以外的备份。
本批只读清点已有业务容器，并在合成环境验证独立控制文件的恢复校验，不删除/恢复真实数据。

## 物理存储清点

新增 `scripts/profile_storage_inventory.py`，仅调用 Docker `ps` / `inspect` 与目录、文件 stat 元数据 API。
扫描 Consumer、Router、Product、Order 命名范围内的当前/停用容器，包括 overlay 可写层、镜像层和挂载源，
不依赖默认 `app.data.dir`。共享镜像层去重，读取到的是物理层，而非容器合并视图，可能包括被遮蔽的旧文件。
不启动、exec、导出或挂载容器，不读取文件正文，也不打印包含用户身份的成员文件名和环境变量。

每个根目录限制 100,000 个条目和 20 秒检查预算，只接受已知容器存储目录及项目目录的非根、非符号链接子路径。
不跟随符号链接，不跨入其他设备；权限/缺失/超限都明确标记，不能把失败当空目录。
仅按旧代码的 `*-memory.md` 格式计数，不证明其他文件格式不包含用户信息。

本轮线上观察：

- 4 个运行容器和 3 个停用 Consumer，前后容器身份、状态、挂载及集合稳定。
- 19 个去重存储位置：7 个可写层、5 个共享镜像层、7 个 JAR 挂载文件。
- 初次扫描 2,700 个条目、1,357 个普通文件；旧记忆文件及同名链接候选均为 0，I/O 错误为 0。
- 888 个镜像层符号链接未跟随，嵌套设备跳过数为 0；7 个 JAR 仅 stat，不打开内部条目。
- 未检查已删除/未注册的容器层，不验证任意远程存储或运行时配置；活跃文件系统观察不是一致性快照。

因此可以补充“已知实例物理层中未观察到旧格式文件”的证据，不能直接把 `LEGACY_STORAGE` 标记成功。

## 控制检查点原型

新增 `scripts/profile_control_checkpoint.py`，纯编码/校验模块，无生产数据库或网络入口。
最小字段为 schema、来源 UUID、指定数据备份 SHA-256、采集时间和控制行：用户 ID、generation、analysis_enabled。
它不保存画像正文、订单、聊天或凭据；对类型、数量、重复身份/字段、未知字段和大小进行严格校验。

恢复调用者必须独立提供期望摘要、来源、数据备份摘要和明确的最大时间差。
变造、错来源、错数据备份、旧控制文件、缺失摘要、未来时间及过期文件均拒绝。
重新开启分析的非零代次不能被现有“统一暂停”演练误处理，必须交给未来单独的重建恢复策略。

**这不是签名系统或生产可信备份。** 摘要若和不可信控制文件放在一起，二者可以一同被替换；
采集时间和行集合只有在独立可信摘要的前提下才有意义。原型不能证明最新删除事件已完整导出。

现有 PG 恢复演练改为：从合成源库读取实际生命周期行，生成控制文件，在容器之外的私有临时目录
单独保存并重读，通过校验后才生成暂停/清理 SQL。测试库限制、事务回滚、重放幂等和其他用户保留不变。
文件只含合成用户，演练结束删除临时文件与自有容器；从未导出真实用户的控制记录。

## 生产落地还需要什么

1. 在每次暂停/删除/重新开启的同一 PG 事务中写最小事件 outbox，带不可重用事件身份和单调序号；
   仅事后定时导出 `profile_lifecycle` 无法证明删除到导出之间没有丢失窗口。
2. 导出到不会随业务库一起恢复的独立控制存储，记录连续序号、水位和校验链。
   清理完成状态必须区分控制记录已持久确认与尚未确认，不能在异步导出失败时仍宣称备份保护完成。
3. 独立维护当前可信检查点；单机 root-only 目录可隔离数据库误恢复，但不是整机丢失后的灾备。
   离线保管或独立存储、访问权限与保留策略需单独确认，不能凭本批临时文件视为已建成。
4. 恢复前关闭业务入口及消费者；按可信水位重放控制记录，并核查 Redis、MQ、文件和派生副本。
   在恢复版本、来源、覆盖及所有目标验收完成前不放流量。重新开启后的合法新代次不能被旧删除记录覆盖。

本批不创建生产导出任务、不配置自动备份、不新增密钥、不开放删除入口。
`LEGACY_STORAGE`、`DERIVED_COPIES`、`BACKUP_RESTORE` 继续 BLOCKED。
