# 客服验收与请求时间预算（2026-09-21）

## 本轮范围

优先推进页面验收、客服回答质量和执行超时边界。浏览器自动化仍返回
`nodeRepl.fetch request failed`，即使用户已在 Edge 打开页面也无法读取标签页。
组件测试不能替代真实浏览器验收，本轮不将该项标记完成。

## 已复现并修复的边界

三个确定性测试在修复前均失败：模型返回超时后仍执行工具、返回迟到答案、同步压缩
耗尽时间后仍开始下一次模型调用。使用注入的单调时钟，不靠 sleep 猜测模型延迟。

- 在压缩后、模型返回/异常后、工具派发前后检查请求预算；恰好到截止时间也停止新工作。
- 模型已返回的 Token 先记账，迟到结果不作为成功答复，不派发它携带的工具。
- 超时不转换为 `ModelCallFailure`，不以模型故障为由启动另一条业务降级流程。
- 工具执行器接收本次请求的剩余预算。并行等待取工具超时与剩余预算较小值；串行
  后续工具和重试开始前再次检查；重试退避超过剩余预算时不再等待和重试。
- 明确未开始的串行工具返回 `NOT_STARTED`。已尝试但未确认的操作保持
  `UNCONFIRMED`、`retryable=false`，不宣称取消等于远端撤销。
- 原有显式取消继续抛出取消信号，不改成可重试模型异常。

**限制：这不是端到端硬超时。** 当前线程中已经开始的同步模型、压缩和单工具调用仍
依赖各自传输层的超时/中断能力；并行回调也可能忽略中断。下一阶段需要逐个核对
模型 HTTP 客户端、Advisor 上下文传播、连接池和远端写入语义，不能用简单异步包装
就声称所有工作被撤销。后台预压缩的完整生命周期也未在本轮重构。

## 客服验收用例与工具

`data/customer_acceptance_cases.json` 包含五个会话、六轮公开场景：

| 场景 | 人工事实/语义验收重点 |
| --- | --- |
| 价格与库存 | 与当前商品目录一致，不擅自承诺分期、库存充足或发货时限 |
| 同会话规格追问 | 正确承接商品，只回答规格，不夹带颜色等未问属性 |
| 蓝牙耳机、两千以内 | 使用品类语义匹配；预算为约束，推荐理由有证据支持 |
| 热门商品 | 区分站内数据和全网趋势，不编造热度依据 |
| 通用退货条件 | 根据资料回答并提供引用，不无故要求订单号 |
| 本人订单列表 | 新注册测试账号应无订单，不跨账号泄漏，不创建订单 |

```sh
python -m unittest discover -s scripts -p test_customer_acceptance.py -v
python scripts/run_customer_acceptance.py --base-url https://xiaoyuai.cloud --report customer-acceptance-report.json
```

运行脚本会注册一个独立测试账号、发起只读业务问题、关闭测试会话、退出并核验令牌
失效。报告只保留测试答复、事件类型、规则结果和复核要求，不保存凭据或原始工具参数。
输出文件已存在时拒绝覆盖。业务查询失败不会跳过令牌和会话清理。

自动检查仅证明完成事件、无错误事件、答案非空及少量主题约束；`semanticQualityCertified`
始终为 false，必须对照业务事实和引用单独评审。测试特意使用荒谬价格证明关键词命中
不能成为质量证书。此数据是公开回归用例，不是独立留出集，也不是模型准确率统计。
模型断网、订单不确定结果、跨用户文档 ACL 等危险/隔离场景继续在专用测试环境验证，
不会为验收而在生产注入故障或提交订单、退款。

## 公开业务验收失败与回滚

候选版本随后完成五个独立测试会话、六轮问题。所有轮次均观察到工具、Token 与 done
事件，五个会话关闭且测试令牌已撤销，但这不等于业务成功：

- 价格/库存、同会话规格追问、站内热门商品和空订单列表返回了对应主题的答复；
  尚未逐项核对全部目录事实，不作为完整语义质量认证。
- “蓝牙耳机、两千以内”最终仅返回查询失败提示，出现 `node_criteria_rejected`。
  对应 Product 日志记录结构化决策 `IllegalArgumentException`；没有记录模型正文，
  因而当前证据不足以确定是哪个字段违反约束。
- 通用七天无理由退货条件被规划为商品任务，最终输出商品候选及办公场景限制，
  未回答政策，也没有引用。原始问题在路由审计记录中完整保留。

首版验收工具将“非空的友好失败回复”算作通过，已补充拒绝事件与失败话术检查，
增加回归用例；没有删除或放宽失败业务场景。原始报告保留在发布目录
`customer-acceptance-report.json`。尚不能据此认定上述业务缺陷由本次执行预算补丁引入。

按上线门禁回滚四个业务服务至 `cross-store-20260921` 记录的原容器和 JAR。
回滚前暂停入口、核验业务队列及执行中会话排空；回滚后逐一核对容器 ID、产物哈希及
恢复控制来源 pin，四服务与 Gateway 健康检查通过，公网 `/healthz` 为 UP、首页 HTTP 200。
`rollback.json` 记录恢复成功。候选容器停止并断开业务网络，保留以供排查，未删除业务数据。
