## 持久化与访问控制

服务器接口及数据验收 22 项通过，主要包括：

1. 首页、登录页、健康接口正常；匿名访问管理 API 返回 401。
2. 通过真实注册、登录取得普通用户 JWT；即使同时伪造管理员身份头，GET/PUT 均返回 403。
3. 服务器内网管理接口保存重量 `1200.125g`、视频播放标称续航 `12.5h`、明确不支持主动降噪、来源和核验时间；审计操作人与版本正确。
4. 新 PostgreSQL 连接读到已提交值，`false` 不变成未知；重复迁移不改变已有值。
5. 旧版本写入返回 409；两个同时使用同一版本的保存请求只有一个 200、另一个 409。
6. 负重量、缺来源、数字代替布尔值、额外价格字段返回 400；未知商品返回 404，不会自动新建。
7. Product 实际商品详情调用读取了已存重量、续航、降噪和来源；清空字段后重新读取仍为 null。
8. 两轮验证各自创建的临时商品已精确删除；其余目录记录的指纹未变化，正式目录仍为 318 条。

## 复测发现及修正

> 下列单活跃会话行为是当时的线上记录；2026-09-26 起，同一账号可有多段独立对话，同一会话内仍串行处理请求。

- 初版验证脚本给同一个账号连续创建多个会话，被已有单活跃会话保护返回 `conversation_suspended`。修正为一个会话中的连续提问，不绕开业务保护。
- 线上提问“不计算差额”仍输出了剩余金额。原因是预算详情否定规则只覆盖“不要计算”等形式，遗漏“不计算”和“只说明”。已补充规则及 7 条回归，再部署 Product。
- 修复后本地 Product 170 条、Common 38 条测试全部通过；此前 Consumer 33 条、Gateway 20 条和 Python 遥测 5 条也已通过。

## 验收限制

- 迁移不等于录入商品事实。真实目录尚未补充经核验的重量、续航等数据，严格参数筛选时不能保证有可推荐候选，不会用虚构验收商品填充推荐。
- 内网精确商品详情的第二次自由文本回答出现一次编码转述笔误，质量护栏返回 WARN；保存及读取的结构化字段正确。该次结果不能描述为模型回答全面无误，原始响应已保存在本地验收 JSON。
- 管理员参数编辑前端尚未新增；本次验收主要是 HTTP、PostgreSQL 与真实对话链路。
