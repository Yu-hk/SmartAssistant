# 商品工具证据与 Token 检测修复

## 原因

2026-09-14 复核线上商品咨询：`queryProductInfo`、`getPrice`、`checkStock` 已返回真实商品事实，但 `StreamingProductAgentService` 的忠实度检查只比较 RAG 文档，未纳入本次工具数据。文档没有实时价格和库存时，可能重复调用模型修正，最终仍产生 `UNSUPPORTED_PRODUCT_CLAIMS` 提示。

另一个告警来自检测脚本：使用 `next(token_usage)` 取得第一条节点进度，其 `tokenUsageComplete=false` 是正常设计。最终事件应在 `response` 之后、`done` 之前读取，不能通过数字非空来推断完整，也不能把缺失当成 0。

真实忠实度校验器回归另发现：原数字表达式漏掉不带千分位逗号的四位及以上价格，并用子串包含判断证据，导致 `4999` 可能漏检、`999` 被 `1999` 错误支撑。本次修正数字识别与规范化后的精确数值匹配，保留百分比与普通数值的区别。

## 修复边界

- 商品同步执行打开一次 `ProductToolEvidenceScope`，只收集本次实际执行的商品只读工具成功返回。错误、不可用结果不作为事实；不记录用户消息、画像或模型回答。
- 忠实度校验和一次有界修正使用 RAG 与工具证据的并集；不能因为“调用过工具”就无条件通过。新增事实仍需再次校验，不支持的断言继续告警。
- 商品问答、分析、推荐校验对用户明确提出的预算复述做窄范围排除，兼容 `预算6000元` 和 `6000元预算`。仅排除相同预算短语，不把用户全文加入事实证据；回答若把 6000 元写成商品售价或擅自改成 7000 元预算，仍接受正常数字校验。其他未识别表达保守地按原规则处理。
- 工具证据在线程内按调用隔离并自动清理，支持嵌套调用；最多保存 12,000 字符，超长观察整条丢弃。没有可采集的工具证据时继续原来的保守校验。
- 当前 Product 工具执行为同步调用；未来若迁移到异步工具线程，必须显式传递独立的调用作用域，禁止跨用户共享缓冲区或仅按会话 ID 收集。
- 成功查询且明确返回 `products=[] / productCount=0` 的目录结果为正常 `PASS / EMPTY_PRODUCT_CATALOG`。缺失上游数据、失败节点或非空冲突仍不得伪装成“无匹配”。场景适配、未证实商品规格等真正的证据限制继续保留。
- 忠实度规则仍是启发式一致性校验，并非语义正确性的完整证明；本次没有关闭质量校验或凭空补充业务数据。
