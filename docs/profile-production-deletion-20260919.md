# 生产画像删除与恢复保护

本轮上线状态：**2026-09-19 已部署，公网专用测试账号验证通过**。侧栏入口为“画像与隐私”。浏览器自动化连接超时，未完成真实浏览器视觉核验；前端交互测试、公开页面及静态资源哈希校验已通过。

## 对用户承诺的范围

- 用户在“画像与隐私”中主动确认后，先暂停后续画像分析，再异步清除在线画像、实体偏好、Agent 记忆、提交候选、画像/答案缓存和可归属的在线派生诊断。
- 不删除账号、订单、原始对话、评价或用户导入的文档。不支持自行重新开启分析。
- 备份按独立保留策略管理：2026-09-20 经用户授权清理旧备份，仅保留最新一套；旧日志仍保留。`ONLINE_CLEANED` 仅表示五项在线清理/恢复控制检查已通过，不表示历史原件物理擦除，也不是注销账号。备份轮换不是对所有用户完成物理擦除的证明。
- 独立控制目录 `/opt/smart-assistant-control` 与业务数据库分离，但仍在同一服务器；不覆盖整机/磁盘丢失、整盘回滚或 root 主动篡改。

## 删除链路与边界

1. Gateway 校验登录与限流；Consumer 隐私接口再次验证 access JWT 的签名、到期、类型和 Redis 撤销记录。身份取自已验证声明，不接受请求体或 `X-User-Id` 指定他人。
2. 同一 PostgreSQL 事务锁定用户生命周期，递增 generation、暂停分析、生成幂等清理任务，并写入连续序号的控制 outbox。事务失败不会留下半次删除。
3. 控制归档器将不含正文的控制事件写入独立目录：固定来源、连续序号、哈希链、文件及目录 fsync、原子 HEAD 和 POSIX 文件锁。回滚后的旧数据库不能覆盖更高版本控制记录。
4. 清理器逐项记账和重试。迟到的分析/缓存/诊断写入使用同一生命周期锁或代际栅栏；删除后不能重新写回旧画像。未版本化的旧个性化缓存/文件写入路径退出生产运行。
5. Consumer、Router、Product、Order 的画像读取/发布均检查独立恢复控制。控制记录缺失、权限错误、数据库落后或历史不一致时，停用可选画像，不假装成功、不阻塞正常业务咨询。

五项收据分别为 PostgreSQL 画像、Redis、在线遗留文件、派生诊断、独立恢复控制。任何一项未通过均为 `PARTIAL`；旧的会话级执行图无法可靠归属时不删除共享键，等待到期后重试。页面显示真实状态，不把重试提示为完成。

## 当前核验证据

- 历史核验：5 份真实 PostgreSQL 备份曾在专用、无网络、临时内存数据库中恢复并核对计数；当时保留原件，2026-09-20 后按最新备份保留授权清理。数据-only 备份借助原表的 schema-only 定义恢复，部分 SQL 需要隔离 NOLOGIN 角色。这不等于可直接恢复生产全站。
- 2026-09-20 新备份 `/opt/smart-assistant/backups/latest-20260920/database.dump` 已在无网络、无生产挂载的临时 PostgreSQL 中完整恢复（37 张 public 表），退出码为零，临时实例已移除。恢复业务流量前仍必须按下述规程核对独立控制来源、重放删除控制并清理派生数据；单独恢复数据库不代表全站恢复完成。
- 其中旧系统备份含 52 条有用户编号的调用记录，涉及 6 个用户；不输出正文或用户编号。其他审计记录不能仅凭数量认定为画像或判断归属。

- 当前/退役的 7 个 AI 容器、19 个物理存储根目录完成扩展文件名清点，未发现画像文件候选，扫描无 I/O 错误。旧 Redis 画像/答案/摘要键为零；64 个执行图均有不超过 24 小时的剩余 TTL。现场计数会随运行变化。
- 本地及服务器最终产物的 Linux 64 项隔离测试通过：清理重试/回滚、跨用户保护、迟到写入、缓存前缀隔离、控制持久化、旧 DB 拒绝读取、文件软链接安全。前端 3 项隐私交互测试、3 项服务入口回归和构建通过。

## 恢复操作规程（不是自动开流量脚本）

1. 停止 Gateway、User 和全部 Consumer/Router/Product/Order 实例，确认没有旧版本或旁路实例。保留独立控制目录，**禁止用备份覆盖该目录**。
2. 先在无网络隔离数据库恢复备份，补齐当前增量 schema。历史真实备份只用于获批的隔离核验，不自动覆盖生产库。
3. 使用提前保管的来源 UUID 校验独立控制文件。不要从已恢复数据库重新生成丢失的来源 pin。
4. `scripts/profile_control_recovery.py --control-dir <独立目录> --expected-source-id <部署固定来源>` 默认只校验并输出数量。`--apply-container` 仅允许专用隔离恢复容器，或者显式 `--offline-production` 且生产业务容器全部停止。
5. 重放会原子恢复暂停控制、清除旧画像/提示词派生内容、重新生成五项 PENDING 收据；保留原始聊天和其他业务数据。它**不会**宣称 Redis/文件也已清理，不会启动流量。
6. 保持当前带恢复保护的版本和挂载，完成 Redis/遗留文件适配器检查与定向验证后，再开放 Gateway。不能回退到忽略独立控制的旧二进制。

硬限制：控制事件最多 10,000；每用户单次扫描最多 500 个派生 Redis 键/诊断会话和有界文件数量。超过限制保持未完成并要求运维扩容/分批方案，不截断后谎报成功。目录权限为 0700、文件 0600；Consumer 可写，其他三个画像使用服务只读挂载。

生产 Compose 已强制四个画像使用服务配置固定 `PROFILE_CONTROL_SOURCE_ID` 并挂载已存在目录（不自动创建空目录）。关闭删除入口只设置 `PROFILE_CLEANUP_ENABLED=false`，不能关闭恢复保护。首次部署应先完成增量迁移、隔离验证及私有目录初始化；后续部署必须保留原 source pin，不可套用无保护的旧 Compose/发布脚本。
