# 模型优先与分词兜底

正常请求仍由模型理解与分配。只有真实模型调用异常时才启用备用流程；不把关键词规则放在正常模型调用之前。意图模型的余额、认证、超时等调用异常保留为类型化失败；商品节点的模型失败也可退回已验证的商品事实查询。业务无数据、质量不通过不等同于模型不可用。

## 备用流程

- IK 分词保留原词与原句，不过滤否定词。商品字段查询仍须通过 Product 的完整句式及唯一目录匹配，使用固定模板，仅回复用户所问字段。
- 下单缺参时展示完整输入格式；本版仅支持明确单件商品、收货人、手机号及地址。金额取自 Product 核实的正价格与可售库存，不使用用户文本自报价格。未核实或歧义时不创建订单。
- “取消订单 ORD-xxx”与“申请退款 ORD-xxx”分别进入既有取消/退款流程。“退单”“退货”不默认等于退款，先澄清。
- 否定、条件、混合操作、重复词槽、格式外参数不执行写操作。未承接的需求明确告知备用能力限制，不假装业务成功。

## 安全与执行边界

Router 产生固定、校验过的 ExecutionPlan，仍通过原 LangGraph 确认暂停、用户归属检查、检查点、幂等和 Order 状态机执行。确认信息含商品、单件金额与收货信息；确认前不调用订单写节点。备用图禁止模型重规划及标题模型抽取，回复直接组合流程模板。

如果原模型流程已开始执行业务，不再重新发起任何备用写流程，避免网络/模型异常后的重复提交。备用流程不进入语义答案缓存，也不会更改模型供应商、密钥或余额设置。

这是有边界的首版：不支持多件自动下单、条件下单、任意自然语言收货信息抽取、无证据的品类别名推断。用户需按澄清提示重新提供完整字段。模型故障前已有用量保留，缺失用量不能被宣称为零。
