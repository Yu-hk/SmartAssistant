# 服务入口修复与画像副本治理进展（2026-09-19）

## 服务入口

重复点击会触发两个问题：每次点击都立即创建本地空会话；首页输入框与文档面板使用相同的兄弟节点 key，
切换空会话时 React 保留了重复节点。现在入口只准备草稿，首次发送再创建会话；输入框和文档面板分别使用
`composer:`、`documents:` 前缀。连续点击、交替选择和切换旧空会话均只保留一个输入框。
不清理已有会话，不覆盖用户编辑过的草稿；请求处理中禁用服务入口。

不消费 MQ、不执行 Redis GET/HGETALL，也不删除数据。Redis SCAN 是动态观察值，不是事务一致快照。

## 已移除的派生缓存

- Consumer `UserProfileService` 的去重 future 不再返回/长期保存画像正文，只表示完成（空字符串保留源兼容性）；
  请求投影仍通过带代次校验和用户索引的 Redis 发布。缓存键仅保留用户/请求身份和问题摘要。
- `UserGroupingService` 不再保留 5 分钟本地偏好分组，也不将可读偏好分组或异常全文写入日志。
  每次从受控存储读取，暂停或存储故障时不能复用旧分组。兼容清缓存方法保留为空操作。
- 这不等于取消/擦除正在运行的模型调用、历史日志或执行图；这些目标继续待验收。

## 合成数据备份恢复演练

本地及服务器运行 `scripts/profile_restore_drill.py`，使用真实项目迁移、`pg_dump`、`psql`，
创建无网络、tmpfs-only、无生产挂载的专用容器。只使用两个合成用户，不读取真实备份。
执行后按精确容器 ID 和自有标签移除测试容器，不影响其他容器、卷或业务数据。

已验证：

1. 恢复删除前备份确实重新带回旧画像和旧生命周期状态。
2. 独立控制标记在事务内重放：暂停分析、推进代次，再清理五张画像载荷表。
3. 中途 SQL 故障全部回滚，不产生部分清理；重复重放结果相同。
4. 旧准入不能在新代次继续有效；过旧标记和缺失/非法控制清单拒绝执行。
5. 未清理用户的五类画像、所有用户/会话、不可变准入摘要保持完整。

脚本只允许 `profile_restore_drill_restored` 测试库，**不是可直接执行的生产恢复工具**。
测试中的外部标记是合成夹具，不证明生产墓碑备份具有权威性、完整性或时序一致性。
真实恢复还必须具备独立可靠的控制标记来源，并在放流量前核查 Redis、MQ、文件、执行图和审计副本。
本轮仍不得将 `BACKUP_RESTORE` 回执改成成功。
