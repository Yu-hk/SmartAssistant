# 实体约束与证据保留校准（2026-10-01）

## 结论

针对[上一轮](native-retrieval-calibration.md)定位的“单路重要资料被多路共同噪声挤出 Top-5”，新增一个**仅供隔离探针使用**的冻结策略：保留原问题、按明确产品名称绑定子句、保留有界证据席位。没有修改业务源码、上线拆分、调整生产权重或开启评估驱动的自动重检索。

65 份合成文档、64 个冻结问题、5 个策略、3 个独立 JVM，共 960 组排名输出，三轮完全一致。新方案在 40 道留出正例上的文档 ID Recall@5 为 1.000，简单拆分为 0.975；新方案保住了后者遗漏的两道题。**原始检索基线同样为 1.000，开发集仍选择基线，因此保留线上现状。** 这不证明完整生产召回率为 100%，也不是 Ragas 四维评分或统计显著性结论。

## 策略边界

`hybrid-anchored-coverage` 只在 `anchored-coverage-v1` 白名单实验配置中加入；旧 `native-v1` 的四策略保持兼容。

1. 原问题始终参与检索，原生 Top-5。
2. 仅接受 2～3 个分号子句，每句至少四个字符。每个子句只有一个明确名称时绑定该名称；未点名的子句仅在整问只有一个名称时继承。歧义、未知、过短或子句过多时退回原问题，不丢弃部分条件。
3. 名称来自公开 Product 合成文档的 `category`，最长字面匹配优先，不使用金标、参考答案或受限文档元数据。这不是完整商品语义识别，不处理别名、历史指代、否定与复杂句法；多个明确名称的契约检查不等于真实多商品质量验证。
4. 每个子句取原生 Top-10，使用完整原 ACL 调用。先记录未过滤候选，再按绑定名称过滤；不额外读取未召回文档。当前实验强制公开 ACL，不声称验证所有登录身份或 PostgreSQL 后端。
5. 每路非空子句保留第一个候选，去重后再保留原问题第一个候选；剩余席位按 RRF 常数 60 填充，最终不超过五个文档。最多原问题加三个子句、四路原生查询；没有在线重试或模型改写。

**席位只保护候选，不证明候选支撑事实。** 同一文档可能占据多个子句的首位；此时仅保留一个席位。也不保证保留全部原 Top-5。例如翻页钟第二路首位仍为 A，B 是从原问题及其余融合席位保住的，不能把最终覆盖归因于“每个事实都被正确识别”。后续需要真实目录身份、字段覆盖和证据支撑检查，再考虑接入在线只读流程。

## 冻结数据与真实结果

`data/anchored_retrieval_questions.json` 使用全新的 30 个虚构产品族，每族两份说明书、明确名称/多事实两种问题；10 个开发族共 20 题、20 个留出族共 40 题。另有四份受限 Product 文档及四道 ACL 守卫题、一份公开 Order 域诱饵，共 65 文档/64 题。问题和文档 ID 不与上一轮数据重合；参考 ID 在采集前冻结，不发给 Java 探针。资料未经业务专家独立审核，不作为真实商品指导或数据库种子。

两道丢失资料的留出题：

- `hold-coffee-compound`：水箱到位与冲煮前预热。简单拆分中 `HOLD-COFFEE-A` 为第一路第一，第二路未进入 Top-10，合并时被共同噪声挤出；新策略保留 A、B。
- `hold-clock-compound`：翻页拨盘方向与放置晃动。`HOLD-CLOCK-A` 同样为第一路第一、第二路未进入 Top-10；新策略保留 A、B。

这两题是新留出集上的重现，不是重新跑过上一轮已知的相机/手表题；不宣称已验证那些旧题的修复效果。新方案相对基线没有逐题召回退步，但也没有收益证据。需要更接近生产分布、经专家审核的困难样本，再评估复杂度和延迟是否值得。
