# 执行层拥有的补全表单

## 职责与边界

- Product / Order 执行层依据当前操作和已解析输入返回 `clarificationRequest = {domain, operation, fields}`，不再让 Consumer 根据最终回复猜字段。
- 共享协议只校验允许的操作与字段组合，不决定当前缺少什么。商品精确查询允许商品/型号；商品发现允许品类、预算、重量；创建订单允许商品和收货资料；物流查询允许订单号；退单、退款、售后各自限定订单号、原因、售后类型。
- 商品发现的字段由产生追问的同一业务分支返回。无法完整表达的续航、测试场景、多选条件保留文字澄清，不用重量等其他字段代替。
- 订单准备通过 Order 的只读 `CLARIFY_INPUT` 能力执行。Router 不再将全局 `missingSlots` 复制到各节点表单；旧的内置准备节点仅作为兼容编排标记，实际资料检查委托 Order。
- 成交金额不作为用户补全字段，也不以预算代替；商品价格、库存、订单归属、状态与审批仍由原业务流程核验。资料补全不是写操作授权。
- 尚未返回结构化协议的模型回复或其他领域仅显示文字，不再通过通用分类模型补造表单。

## 传递和安全

- Router 保留域结构化数据，并在最终响应传递唯一可信补全请求。同一请求沿商品分析链重复传递可去重；不同领域/不同操作请求不拼成一张表单。存在必要步骤失败或待审批时不发放表单。
- 多任务合并不再用模型重写已有结构化补全问句。补全结果不写入商品节点缓存。
- Consumer 仅审核协议、签发凭证、呈现和校验提交。凭证新增绑定领域与操作，保留账号、会话、来源回合、有效期、最新归属记录、防重和原子活跃会话门禁。
- 未绑定领域/操作的旧凭证拒绝提交；不改写历史回复。
- 历史加载只恢复执行层曾返回的字段。Redis `clarification:permit:<hash>` 保存字段标识、领域、操作和到期时间，TTL 15 分钟；不保存正文、输入值、用户标识明文或令牌。签发历史凭证不延长最初到期时间。缓存不存在、过期或不可用时仍可文字补充。
- 手机号限 11 位中国大陆格式；收货姓名最多 40 字，地址/原因最多 200 字；售后类型限定退货、换货、维修。前后端校验一致，业务真实性仍需执行层验证。
- 无数据库结构迁移。Consumer 的后置字段分类器已删除，不再产生额外分类调用与 Token 开销。
