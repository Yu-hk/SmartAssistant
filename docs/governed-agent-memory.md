# Agent 记忆写入与读取隔离（2026-09-19）

继续落实 [画像删除协议](profile-erasure-proposal.md)，本批收敛订单 Agent 的异步偏好提取。
不开放删除/恢复入口，不自动迁移或删除历史文件，不把防止旧写入等同于全量物理删除。

## 运行路径

- `OrderAgentController` 在只读知识和正常 Agent 回答后将 requestId 传入 `MemoryExtractor.extractAsync`。
  原先的公共异步线程池调用改为独立 2 线程、无队列、拒绝时跳过的可选任务；不在业务线程提取。
- 模型调用前，按用户、请求哈希、**原话哈希**查询 Consumer 已保存的准入凭据，
  与 `profile_lifecycle` 当前启用代次联查。缺凭据、暂停、旧请求和被模型改写的问题都跳过。
  不给旧请求补发新代次，不将 RAG 内容或助手结论当成用户事实。兼容请求若无法保持原话一致，
  宁可不生成可选记忆；订单正常问答不受影响。
- 提取结果整批保存到 `profile_agent_memory`，与电商快照分表，属于低可信历史参考，
  来源为 `POSTGRES_AGENT`。用户/Agent/键构成主键，最多 10 条候选，键格式和值长度校验，
  生命周期行锁与整批写入共用一个 PG 事务。模型返回晚于暂停/清除时，整批拒绝且不重试重建。
- 读取在同一 SQL 内过滤当前代次、启停和有效期。业务门面另设独立 2 线程无队列读取池，
  最多等待 100ms，异常/忙碌返回无可选记忆，不回退到本地文件。
- 取消为协作式中断，不能保证数据库驱动或模型供应商立即中止；忽略中断时工作位保持占用，
  后续可选任务跳过。已返回的上下文不能撤回。本批不宣称供应商内容已经删除。

## 兼容与数据边界

Spring 生产构造始终使用受控 PG 存储；旧无请求 save/delete 方法拒绝执行。
单参数文件构造仅保留给离线兼容与文件并发回归，不能重新注册为生产 Bean。
旧工具依然不在 Product/Order 回调清单，摘要不再推荐调用已关闭的 `recallMemories`。

旧容器文件不自动读入新存储，也不删除；因此旧文件中的偏好不再参与生产回答。
新事实保留 90 天读取有效期；物理过期清理/用户清理仍需后续统一任务，不能把到期不可读说成已物理删除。
PG 记录时间是持久化时间，不是用户原话发生时间。账号、聊天、订单不在本批删除范围。

## 发布与验收

先执行 `20260919_add_governed_agent_memory.sql`，再升级 Consumer、Router、Product、Order 的共享库产物。
变更仅新增表/索引；不将删除任务状态改为完成。回滚保留新增表/准入凭据，启用生命周期变更后
禁止退回旧文件写入二进制。其他共享库消费者不新增记忆调用入口。

真实 PG 测试覆盖准入、原话一致性、暂停/恢复、跨用户/Agent、无效批次、事务回滚、过期、
模型迟到和并发清理。单元测试覆盖生产 Bean 装配、无文件后备、来源标签、代次不重捕获、
100ms 可选读取和后台提取满载。本地与服务器隔离库仅使用合成用户。
