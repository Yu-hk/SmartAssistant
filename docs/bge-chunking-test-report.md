## 一、分块策略体系总览

项目中的文档分块实现了三层策略，依次递进：

```
文本输入
    │
    ▼
┌─────────────────────────────────────────────┐
│  SemanticChunkStrategy   ← 主策略            │
│  按# ##、第X章、一、二、三 等语义边界切分      │
│  maxTokens=1024(默认),  overlap=128          │
└────────────┬────────────────────────────────┘
             │ 超长段落
             ▼
┌─────────────────────────────────────────────┐
│  RecursiveChunkStrategy   ← 回退策略          │
│  按\n\n→。！？→；→，→空格→固定长度递归切分    │
│  MIN_CHUNK_CHARS=20                         │
└─────────────────────────────────────────────┘
             │
             ▼
┌─────────────────────────────────────────────┐
│  ParentChildDocumentChunker  ← 双粒度编排     │
│  子块(256tok,检索用) → 父块(1024tok,阅读用)  │
└─────────────────────────────────────────────┘
```

### 各策略核心参数

| 策略 | 参数 | 默认值 | 用途 |
|------|------|--------|------|
| `SemanticChunkStrategy` | `maxTokens` | 1024 | 语义块最大 token 数 |
| | `overlap` | 128 | 块间重叠 token 数 |
| | `MIN_CHUNK_CHARS` | 20 | 最小块字符数 |
| `RecursiveChunkStrategy` | 分隔符优先级 | `\n\n` > `。！？` > `；` > `，` | 递归降级直到不超限 |
| `ParentChildDocumentChunker` | `childMaxTokens` | 256 | 子块（检索用） |
| | `parentMaxTokens` | 1024 | 父块（LLM阅读用） |
| | `overlap` | 50 | 子块重叠 |

## 三、测试结果

### TCG-02a：Markdown 文档 — 小阈值语义拆分

**配置**: `maxTokens=200, overlap=20`

| Chunk | Token | 内容预览 |
|-------|-------|---------|
| #0 | 165 | `# SmartAssistant 订单系统使用指南 ## 1. 下单流程 用户可以通过...` |
| #1 | 164 | `### 1.2 立即购买 点击"立即购买"按钮会跳过购物车... ## 2. 支付方式` |
| #2 | 50 | `## 3. 退款政策 订单支付后未发货可全额退款...` |

- **下单** ✓ | **支付** ✓ | **退款** ✓
- 三个 # heading 被正确识别为语义分界点

**观察**: 200 token 阈值下，Markdown 文档被拆分到 ## 标题层级，同一父标题下的子标题(###)被合并为一个 chunk。

---

### TCG-02b：中文章节文档 — 小阈值语义拆分

**配置**: `maxTokens=150, overlap=15`

| Chunk | Token | 内容预览 |
|-------|-------|---------|
| #0 | 92 | `北京旅游攻略 一、必游景点推荐 故宫博物院位于...` |
| #1 | 110 | `二、美食推荐 北京烤鸭是最具代表性的北京美食...` |
| #2 | 54 | `四、住宿建议 王府井地区靠近故宫天安门...` |

- **景点** ✓ | **美食** ✓

**观察**: `一、` `二、` 等中文数字标题被识别为语义边界。**注意** `三、交通出行` 内容短，被合并到 `二、美食推荐` 所在的 Chunk#1。

---

### TCG-02c：纯文本 — 回退递归拆分

**配置**: `maxTokens=200, overlap=20`

| Chunk | Token | 内容预览 |
|-------|-------|---------|
| #0 | 168 | `SmartAssistant Pro 智能音箱...搭全新的 AI 语音助手...` |
| #1 | 112 | `智能音箱支持智能家居控制...还支持闹钟提醒...` |

- 2 个 chunk 全部在 Token 阈值 (200+30) 内 ✓

**观察**: 纯文本无 Markdown/中文标题，`SemanticChunkStrategy` 按换行(段落边界)切分后合并回退。结果 2 个 chunk 分别覆盖"产品介绍/配件/开机"和"智能家居/实用功能/客服"。

---

### TCG-02d：大阈值合并行为

**配置**: `maxTokens=1024, overlap=128`（生产默认值）

| 文档 | 字符数 | Chunk 数 |
|------|--------|---------|
| Markdown | 463 | **1** |
| 章节文档 | 307 | **1** |
| 纯文本 | 333 | **1** |

- 合并后 chunk 内容完整，覆盖原文所有章节 ✓

**结论**: 当文档总 token 数不超过 `maxTokens=1024` 时，`SemanticChunkStrategy` 将全部段落合并为一个完整块——这是设计意图，减少碎片化 chunk 对检索的负面干扰。

### TCG-05a：策略对比（语义 vs 递归）

**配置**: `maxTokens=1024`

| 文档 | 语义分块数 | 递归分块数 | 差异 |
|------|-----------|-----------|------|
| Markdown | 1 | 1 | 相同 |
| 章节文档 | 1 | 1 | 相同 |
| 纯文本 | 1 | 1 | 相同 |

**说明**: 在 `maxTokens=1024` 下三份短文档均整篇为一块，故两种策略输出一致。差异在超长文档或小阈值场景下体现。

---

### TCG-05b：语义分块保留章节标题

**配置**: `maxTokens=150`

- 语义分块后的 chunk 包含章节标题（如 `一、` `二、`）：**true** ✓

**结论**: 语义分块将章节标题作为 chunk 的起始内容，保留了文档的章节结构信息。

---

### TCG-06：Parent-Child 双粒度分块

**配置**: `childMaxTokens=256, parentMaxTokens=1024, overlap=50`

| 指标 | 值 |
|------|-----|
| 输入文档 | 订单指南 + 旅游攻略 = 2 篇 |
| 父块（阅读用） | 2 个 |
| 子块（检索用） | 4 个 |
| 父块平均 Token | 318.5 |
| 子块平均 Token | 159.0 |
| 子块 < 父块 | ✓ |
| 子块关联父块比例 | 100% ✓ |

**Parent-Child 关系结构**:

```
doc-01 (订单指南)
  ├── parent-0 (父块, 阅读用)
  │   ├── child-0 (子块, 检索用)
  │   ├── child-1 (子块, 检索用)
  │   └── child-2 (子块, 检索用)
  │
doc-02 (旅游攻略)
  └── parent-1 (父块, 阅读用)
      └── child-0 (子块, 检索用)
```

**结论**: Parent-Child 分块正确工作——所有子块关联到有效父块，且子块平均大小(159 token)约为父块(318 token)的 **50%**，体现了"小块检索、大块阅读"的设计目标。

## 四、综合结论

| 维度 | 表现 | 评分 |
|------|------|------|
| Markdown 标题识别 | `# ## ###` 精确切分 | ★★★★★ |
| 中文章节识别 | `一、二、三、` `第X章` 正确识别 | ★★★★★ |
| 无结构文本回退 | 按换行→段落递归切分 | ★★★★☆ |
| Token 边界合规 | 严格 ≤ maxTokens + 少量浮动 | ★★★★★ |
| 合并策略 | 短文档合并为完整块，减少碎片 | ★★★★★ |
| Parent-Child 结构 | 子块:父块 = 1:2 粒度差合理 | ★★★★★ |
| 章节标题保留 | 标题在 chunk 开头，语义完整 | ★★★★★ |

**一句话结论**: BGE 分块体系在结构化文档（Markdown/章节）上的语义边界识别准确，在纯文本上回退递归分块可靠，Parent-Child 双粒度结构正确。生产默认 `maxTokens=1024` 对短文档的合并行为避免了碎片化 chunk，兼顾了检索精度和上下文完整性。
