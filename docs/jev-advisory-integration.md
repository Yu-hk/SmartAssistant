# Jev 辅助决策接入

Jev 是可选的辅助判断，不是订单写操作授权，也不是商品事实来源。接口格式参见 [TypeSafe OpenAPI](https://api.typesafe.ai/openapi.json)。默认 `JEV_ENABLED=false`；无密钥或调用失败时原流程继续。

| 时点 | 所属服务 | Jev 的作用 | 不可越过的边界 |
| --- | --- | --- | --- |
| 入 MQ 前 | Consumer | 限时评估负面情绪和紧急程度；结合 `jev/prequeue-risk.properties` 的可审查风险信号，影响队列优先级与回复语气 | 不能声称已人工转接；超时不阻断聊天；不能从客户端接收优先级 |
| 任务规划 | Router | 不调用 Jev，继续由现有规划器拆分跨领域、多意图任务 | 不把商品与订单混合问题压成一个 Jev 单选标签 |
| 商品执行 | Product | 仅在确定性解析未命中、且存在商品品类或特征线索时，辅助识别“商品发现” | 明确商品事实查询不改道；价格、库存、匹配条件仍以目录和确定性校验为准 |
| 订单执行 | Order | 主模型不可用且确定性兜底无法识别时，辅助识别只读订单意图 | Jev 永不返回可执行写操作授权；下单、退款、取消等仍走既有鉴权、字段校验和幂等流程 |

三个问题目录分别位于 Consumer、Product、Order 的 `src/main/resources/jev/`。业务类别和问题措辞可通过资源文件审查与版本管理，不向 Router 复制领域字段规则。

## 启用与回滚

在需要启用的服务运行环境中配置 `JEV_ENABLED=true` 与新的 `TYPESAFE_API_KEY`。可选 `JEV_MODEL`（默认 `jev-latest`）、`JEV_TIMEOUT_MS`（默认 600，限制在 100–2500）和 `JEV_PROXY_URL`。不要把密钥写入仓库、镜像、命令行参数或日志。关闭 `JEV_ENABLED` 并重启相应服务即可回退到原有判断链。

启用意味着把经过基础脱敏的用户当前提问发送到第三方：邮箱、手机号、`ORD-...` 编号、长数字标识和 UUID 会被替换；这**不等于完整的个人信息匿名化**。上线前应完成数据传输与隐私审批，轮换此前在聊天中发送的密钥，并以最小范围逐项启用。长度超过 1500 字符的文本不会发送。

Jev 结果均有置信度门槛并有调用超时。Consumer 在整个预处理预算内执行，超时按既有未知情绪路径继续。模型返回 token 用量会计入本轮用量；提供方缺失用量时不得将部分统计当作完整总量。日志只记录失败类型或 HTTP 状态，不记录请求正文、密钥或响应正文。

## 验收重点

1. 无配置、超时、401/403、无用量响应时，聊天仍可继续且不会产生订单写操作。
2. “重复扣款”可在入队前提升优先级；低置信度 Jev 分数不能提升优先级。
3. “AirPods Pro 多少钱”继续查商品事实，不被当作商品推荐；含品类的模糊选购需求可进入目录发现。
4. “有货吗？退款到账了吗？”继续由 Router 拆为商品与订单任务，不由 Jev 的单选结果裁掉一个任务。
5. 订单主模型失败时只允许 Jev 辅助只读意图；“我要退款”等写请求保持 `OTHER`，绝不自动执行。
