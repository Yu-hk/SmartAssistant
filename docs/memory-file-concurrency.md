# Agent 文件记忆并发治理（2026-09-18）

## 问题与修复

旧实现读取整份 Markdown 后覆盖写回，独立 JVM 同时保存/删除可能丢失更新或恢复已删除键。
读取异常曾被当成空 Map；后续保存可能因此覆盖原数据。

`AgentMemoryService` 保持原公共接口及 Markdown 格式，使用 `MemoryFileTransaction`：

- 以同一用户/Agent 文件旁固定的 `.lock` 文件加锁；完整读取、修改、替换在锁内执行。
  不删除锁文件，避免原子替换后不同进程锁住不同 inode。
- 锁争用最多等待 250ms；失败放弃本次可选记忆更新，不影响正常问答。中断保留中断标记。
- 同目录临时文件写完、`force(true)` 后原子替换；不支持原子替换时拒绝更新，不退化为截断重写。
- 仅文件不存在视为空；I/O、UTF-8 解码或大小超限拒绝覆盖，读写上限均为 256KiB。
- 数据路径及侧边锁路径拒绝符号链接；正常完成/异常返回清理本次临时文件。
  读取不加锁，依赖原子替换观察完整旧版本或新版本。

## 边界

这是本机文件系统上、使用同一锁协议的进程间协作，不是跨节点/NFS 一致性协议。
同一键的后到写入仍可覆盖先到写入，不提供业务版本 CAS 或全量画像删除隔离。
250ms 限制锁等待，不是底层磁盘 I/O 总超时。公共 `void` 写接口仍是 best-effort，
锁失败会丢弃本次可选更新，不能将其描述为可靠事件投递。

旧二进制不遵守新锁，不能把新旧版本长期混跑当成并发安全部署。
进程退出由操作系统释放锁，锁文件保留；硬崩溃可能残留临时文件。
不承诺断电后的目录元数据持久性，也不防范具备宿主文件写权限的恶意进程交换父目录。
新文件沿用临时文件的默认权限；当前单机同服务身份运行，不支持依赖不同 Unix 用户组共同写文件的部署。
未重新开放缺少身份绑定的旧记忆工具，不迁移或删除真实用户记忆。
