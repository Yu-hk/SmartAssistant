# 压缩备份目录覆盖（2026-09-19）

接续 [诊断副本治理](profile-diagnostics-20260919.md)，本批补查此前未覆盖的压缩归档。
只部署运维检查脚本，不改 Java/前端运行包、不重启业务服务，也不删除、恢复或迁移真实备份。

## 工具边界

`python3 scripts/profile_archive_inventory.py` 只检查本机 `/opt/smart-assistant/backups`。
支持 TAR、gzip TAR 和 ZIP；独立 gzip SQL、其他格式和外部位置不视为已覆盖。
TAR 为遍历目录头会在内存中进行有界解压，ZIP 只读取中央目录；从不解压落盘，
不执行 SQL，不读取/输出 ZIP 成员正文，不报告成员文件名、用户正文或底层异常消息。

- 每份归档输入及展开遍历预算均为 64MiB，最多 10,000 个成员、20 秒。
- ZIP 中央目录最多 4MiB，提前拒绝超限、分卷和 ZIP64 标记。
- 路径穿越、绝对路径、链接/特殊文件及加密标记均显式阻断，不跟随链接。
- 损坏、不支持、超限、检查期间变化或不可读均记录 BLOCKED；部分扫描不标记目录完成。
- 仅按文件名统计画像/记忆、数据库、Redis 持久化、日志、配置和嵌套归档等候选类别。
  名称规则不能证明内容或所有者，嵌套归档不递归展开。
- `CATALOG_ONLY` 仅表示目录检查完成，不代表压缩包完整性验收或可安全恢复；
  `fullArchiveIntegrityVerified`、`productionRestoreCertified`、`erasureComplete` 均保持 false。

## 线上观察

10 份 `frontend.tar.gz` 合计检查 1,808 个成员，均为 `CATALOG_ONLY`，未命中上述候选名称类别，
未遇到链接、路径穿越或加密标记。本轮没有解析或输出成员正文，也没有验证正文中是否存在敏感信息。
加上上一批 2 份 dump 和 3 份 SQL 的表目录检查，仅扩展了本机已知备份的元数据覆盖，
不等于完成历史数据归属检查，更不能推出云盘快照、外部备份或旧容器均无副本。

用户于本轮明确确认没有该目录之外的云盘快照、OSS、其他服务器或手动下载备份。
后续备份清点以此确认范围为准；这是用户提供的部署范围声明，不是脚本扫描云账号的结果。
