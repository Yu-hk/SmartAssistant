# 实体画像写入隔离（2026-09-19）

继续落实 [画像删除协议](profile-erasure-proposal.md)。本批只收敛 Consumer 实体事实写入，
不开放删除/恢复入口，不清理或迁移已有真实用户数据。

## 调用路径与行为

- 代码追踪发现实体事实提取位于 `ChatConsumerService.calculate` 兼容链路；
  当前页面 SSE 与 `calculateWithSession` 仍使用已有电商画像链路。
  本批不将实体提取扩展到这些入口，不额外增加模型调用或重复画像。
- Consumer 的 `EntityProfileConfig` 现在注入 `GovernedEntityProfileStore`，
  新实体事实保存在 `user_profile_entity_fact`；生产 Bean 不再调用旧 Redis hash 写入。
- 公共库保留旧 Redis 构造入口，供历史兼容与测试使用；它不具备代次保护，
  不能重新接入生产配置。旧 `user:profile:<id>` 数据不会回填 PG 或作为新存储读取失败的后备。
- 实体仍是低可信参考，来源标记为 `POSTGRES_ENTITY`，不是可靠电商快照。
  不合并到快照表，不把助手回复、实体偏好当作价格、库存或业务操作授权。

## 事务与保留期

提取前捕获 generation；模型及关键词回退共用该值。提交在 `ProfileGenerationFence` 的
同一事务和用户控制行锁下检查启停、代次，再保存整批事实。失败整体回滚，旧代次不重试重建。
读取通过一条 SQL 同时约束用户、当前代次、分析开启状态和有效期；暂停或跨代次数据不可见。

允许字段限定为 `name/location/preference/fear/hobby`，每值最多 500 字符，拒绝控制字符和
未知字段；整批先校验，再写入。字段及长度由 Java 与数据库约束共同限制。
继承旧实体事实的 90 天有效期；每次合格更新刷新该字段的有效期，读取立即排除过期事实。
定时物理清理默认每小时最多 500 条，停机/积压可能延迟，不承诺到期瞬间物理删除。
字段 `updated_at` 是持久化时间，不是用户原话发生时间；摘要不伪造事实新鲜度。

## 尚未完成的删除边界

- 当前只在提取开始时捕获代次；请求排队后才执行的情况仍需请求准入代次，
  不能宣称旧排队请求已全部隔离。
- 旧 Redis 实体、旧 Agent 文件、请求缓存、派生审计、供应商与备份副本仍需独立盘点和回执。
- Agent 自动文件提取仍需接入控制面；Redis 用户级墓碑和读取端隔离也尚未完成。
- PG 读取是语句执行时的一致快照，不撤回已经返回或发送给模型的参考内容。
- 完整清理任务、授权接口、备份恢复演练尚未完成，删除入口必须继续关闭。
